# 信用卡模块设计（用卡：该刷哪张）

状态：设计稿，待确认后实施。实施分三期（见第 10 节），第一期不依赖未定的问题。

## 1. 问题与目标

**问题**：家里有几张信用卡，每张在不同场合返现不同（超市 3%、加油 2%、本季度轮换 5%、开卡奖励要在 3 个月内刷满），还有年费、到期换卡、还款日。这些信息散在各家银行的 App 和邮件里，结账时想不起来该用哪张，年费到期也不记得衡量值不值得续；回头看对账单才发现用错卡少赚了返现。

**目标**：把每张卡的「画像」（返现规则、奖励进度、年费、到期、还款）集中记在小助手里；在该做决定的地方——采购清单点「已买到」、补记花费、出门前——直接告诉你该刷哪张、为什么；到期、年费、轮换类别激活、开卡奖励截止日按时提醒；事后用银行导入的数据算出「上月如果用对卡能多赚多少」。

**成功标准**

- 加一张常见卡 ≤ 1 分钟：从内置目录选 → 填尾号、到期月、还款日即可；不常见的卡可手填或让 AI 起草规则再确认。
- 在「用卡」页选场景（超市 / 餐厅 / 加油 / 网购 / 旅行 / 其他 + 金额）1 秒内给出前 3 张卡和理由；采购清单和补记花费旁同样能看到。
- 卡到期前 60 / 30 天、年费前 30 天、季度轮换类别开始时、开卡奖励截止前 14 天，出现在首页「今日」注意事项。
- 「回顾」里能看到上月各卡花了多少、返现估算、如果用最优卡能多赚多少（依赖银行导入的账户标签）。
- 不存完整卡号、CVV、密码；AI 只收到卡的产品名。

## 2. 范围与非目标

**范围**：家庭层面的信用卡（也允许借记卡 / 支付宝微信这类作为「不返现的卡」参与比较）；返现 / 积分规则；开卡奖励与报销额度进度；年费、到期、还款提醒；用卡推荐；事后返现复盘。

**非目标**：不连接银行账户、不抓取网银（没有公开 API）；不算利息、不做分期规划；不做积分兑换最优解（航空里程转点等），积分只按「每点值多少美分」折算成 % 返现来比较；不自动在结账时弹窗（浏览器做不到）。

**安全边界**：只记发卡行、产品名、卡号末四位、到期年月；不记完整卡号、CVV、PIN、网银密码；「谁持卡」记家庭成员 id。AI 起草规则时只发产品名（例如 "Chase Freedom Unlimited"），不发任何个人信息。

## 3. 核心概念

| 概念 | 说明 |
|---|---|
| 卡（card） | 一张实际的卡：发卡行、产品、网络（Visa / Mastercard / Amex / Discover / 银联）、尾号、持卡人、到期年月、年费、信用额度、账单日、还款日。 |
| 卡画像（rewards） | 这张卡在各消费类别的返现率、封顶、季度轮换、特定商家、积分估值、境外手续费。来自内置目录、AI 起草或手填；记「截至日期」。 |
| 奖励类别（reward category） | 发卡行口径的类别：grocery / dining / gas / travel / online / drugstore / streaming / utilities / transit / wholesale / amazon / other。和小助手的花费分类之间有一张固定映射表（第 6 节）。 |
| 开卡奖励（bonus） | 「N 个月内刷满 X 得 Y」：截止日、目标金额、已刷金额（从花费 / 银行导入按账户自动累计，也可手填）。 |
| 报销额度（credits） | 年度 / 季度的固定报销（旅行报销 $300、流媒体 $10/月）：用了多少、什么时候清零。 |
| 推荐（pick） | 给定场景（类别、商家、金额、是否境外、日期）→ 每张卡的「有效返现率」排序 + 一句理由 + 警告（快到期 / 该还款 / 不收这家卡）。 |
| 复盘（review） | 按银行导入的账户标签，把上月各账户的花费按类别汇总，对比「实际用的卡」和「最优卡」的返现差。 |

## 4. 数据模型

一张表，全部挂 `household_id`，RLS 同现有表；规则放 jsonb，改规则不用迁移。演示模式存 localStorage。

```
cards（迁移 032）
  id, household_id
  name            text      卡的叫法，默认 = 产品名（"Chase Freedom Unlimited"）
  issuer          text      发卡行（Chase / Amex / Citi / Discover / 招商…）
  network         text      visa / mastercard / amex / discover / unionpay / other
  last4           text      末四位（可空）
  holder_user_id  uuid      持卡人（家庭成员，可空 = 共用）
  kind            text      credit / debit / wallet（借记卡、支付宝微信也能参与比较，返现 0）
  expires_on      date      到期年月（存当月 1 号）
  opened_on       date      开卡日（算开卡奖励截止、年费周年）
  annual_fee      numeric   年费（0 = 无）
  fee_month       int       年费收取月份（1–12，可空 = 按开卡月）
  credit_limit    numeric   额度（可空；只用来提示「额度用了 80%」）
  statement_day   int       账单日（1–31，可空）
  due_day         int       还款日（1–31，可空）
  autopay         bool      是否自动还款
  bill_id         uuid      关联的「信用卡」类周期账单（还款提醒 / 记录复用账单模块；可空）
  catalog_id      text      来自内置目录的哪张（可空 = 手填 / AI 起草）
  rewards         jsonb     卡画像（见下）
  bonus           jsonb     开卡奖励进度（可空）
  credits         jsonb     报销额度列表（可空）
  rules_as_of     date      规则截至日期（目录 / AI / 手填时写）
  active          bool      停用的卡不参与推荐，保留记录
  notes           text
  created_at, updated_at, created_by
```

`rewards` 的格式（全部是「% 返现等价」；积分卡按 `point_value` 折算）：

```json
{
  "base": 1.5,
  "cats": { "grocery": 3, "dining": 3, "gas": 2, "travel": 2, "online": 1.5, "drugstore": 3, "streaming": 1.5 },
  "caps": { "grocery": { "limit": 6000, "period": "year", "then": 1 } },
  "rotating": [
    { "from": "2026-10-01", "to": "2026-12-31", "cats": ["amazon", "wholesale"], "rate": 5, "cap": 1500, "activated": false }
  ],
  "merchants": { "amazon": 5, "whole foods": 5 },
  "point_value": 1.0,
  "foreign_fee": 0,
  "accepts_only": null
}
```

- `base`：其他一切消费的返现率。
- `cats`：奖励类别 → 返现率。没列的类别按 `base`。
- `caps`：某类别的封顶（年 / 季 / 月），超过后按 `then`（默认 `base`）。进度按花费 / 导入里标到这张卡的金额累计，也可手填「今年已用」。
- `rotating`：季度轮换 5% 类别（Chase Freedom、Discover it）。`activated` 要你每季点一下，没激活按 `base` 并提醒。
- `merchants`：特定商家（Amazon Prime 卡 5%、Target RedCard 5%）。匹配商家名关键词。
- `point_value`：每点折合多少美分（现金返现卡 = 1；航空 / 酒店点数你自己定，例如 1.5）。`cats` 里写的是倍数 × point_value 之后的 %，目录里已折好。
- `foreign_fee`：境外手续费 %。境外场景按 `率 − 手续费` 比较。
- `accepts_only`：网络限制是商家一侧的事，不放这里；放在推荐输入的「商家」上（见第 6 节 Costco 例子）。

`bonus`：`{ "spend": 4000, "by": "2027-01-15", "reward_value": 750, "label": "60,000 UR ≈ $750", "spent": 1230.5, "spent_manual": null, "done": false }`。
`credits`：`[{ "name": "旅行报销", "amount": 300, "period": "year", "resets_on": "2027-01-01", "used": 120 }]`。

## 5. 卡画像从哪来（三层）

1. **内置目录** `data/cards.js`（第一期）：常见卡 20–30 张，北美为主、国内几张（招商、建行常见卡），每张带 `rules_as_of`。季度轮换日历（Chase Freedom、Discover it）按年维护，像 AI 模型目录那样带「更新于」日期，超过 90 天提示「目录可能过期，以发卡行为准」。
2. **AI 起草**（第二期）：目录里没有的卡，把产品名发给你在设置里选的模型，要求按上面的 JSON 格式返回画像；返回的是草稿，逐项显示让你确认 / 改，确认后才保存。能联网检索的模型（Gemini 的 Google Search grounding）结果更新；不能联网的按模型记忆，标「可能过时」。不会定时自动抓取——静态站没有服务器，且发卡行页面没有公开 API；「刷新规则」是手动按钮。
3. **手填 / 手改**：任何时候都能改；改过的字段标「手填」，之后刷新目录不覆盖。

## 6. 推荐逻辑

**输入**：`{ rewardCat, merchant?, amount?, abroad?, date }`。来源：
- 采购清单「已买到」：按条目的花费分类映射到奖励类别，商家取「在哪买」；
- 补记花费：分类 + 商店；
- 「用卡」页的快速查询：你选场景；
- 今日页：当天日期（看季度轮换、截止日）。

**花费分类 → 奖励类别映射**（固定表，放 `data/cards.js`）：

| 小助手花费分类 | 奖励类别 |
|---|---|
| 日常储备各类、grocery_misc | grocery（Costco / Sam's Club 商家名命中 → wholesale） |
| life_dining、travel_dining | dining |
| vehicle_fuel、travel_fuel | gas |
| travel_flight / ship / ground / rental / lodging / tour / tickets | travel |
| life_shopping（商家 amazon → amazon） | online |
| health（药房商家） | drugstore |
| bill_subscription、bill_cable_tv | streaming |
| bill_electric / gas / water / internet / mobile | utilities |
| bill_toll、bill_parking、travel_ground（地铁 / 公交） | transit |
| 其余 | other |

**每张卡的有效返现率**：

```
rate = 轮换类别命中且已激活且封顶未满 ? rotating.rate
     : merchants 命中 ? merchants[x]
     : cats[rewardCat]（封顶已满则 caps.then）
     : base
if abroad: rate -= foreign_fee
if bonus 未完成且 by 未过: rate += reward_value / max(spend − spent, 1) × 100   // 开卡奖励的边际价值：$750 / 剩 $2,000 = 37.5%，自然排到最前
```

**排除 / 警告**：
- 商家不收这个网络（Costco 美国只收 Visa、部分商家不收 Amex）：排除并说明。商家网络限制表放目录里，可自己加。
- 卡 30 天内到期：警告「快到期，确认新卡到了再用」。
- 还款日 3 天内且未自动还款：警告「先还款」。
- 额度用了 ≥ 80%（有额度和本期花费数据时）：警告。
- 轮换类别本季未激活：排在前面但标「先去激活」。

**输出**：前 3 张，每张一句理由：「Amex Blue Cash · 超市 6%（本年封顶还剩 $2,140）」「Chase Freedom · 本季 5%：Amazon / 仓储超市（未激活！）」。金额已知时同时显示能返多少钱。

## 7. 提醒（接现有提醒总线，source = "card"）

| 提醒 | 时机 | 严重度 |
|---|---|---|
| 卡到期 | 到期前 60 天「留意」、30 天「尽快」、过期「紧急」 | 3 / 2 / 0 |
| 年费 | 收费前 30 天：「年费 $95 下月收，今年返现估算 $X，值不值得续」 | 3 |
| 季度轮换 | 季度第 1 天：「本季 5% 类别：…，去激活」直到你点「已激活」 | 2 |
| 开卡奖励 | 截止前 30 / 14 / 7 天，带进度条「还差 $1,200，还有 12 天」 | 3 / 2 / 1 |
| 报销额度 | 周期结束前 30 天还没用完 | 3 |
| 还款 | 复用账单模块：卡关联一条「信用卡」类周期账单（有「创建还款账单」按钮），到期 / 核对提醒和缴费记录都走账单那一套，不重复做 | 账单原有 |

## 8. 界面

- **账单 → 用卡**（新的二级页，和「花费」「预算」并列）：
  - 顶部「现在该刷哪张」：场景选择（超市 / 餐厅 / 加油 / 网购 / 旅行 / 其他）、可选金额、境外开关 → 前 3 张卡卡片式展示；
  - 卡列表：每张一行——卡名、尾号、网络、持卡人、到期、本季轮换类别、开卡奖励进度条、年费；点开编辑；
  - 「本月各卡花了多少」小图（依赖银行导入的账户标签）。
- **采购清单**：待购买条目点「已买到」前，输入框旁一行小字「建议用 Amex Blue Cash（超市 6%）」；点一下展开前 3。
- **补记花费**：选了分类后同样一行小字。
- **今日页**：有卡相关提醒时在注意事项里；季度第一周显示「本季 5% 类别」小块。
- **回顾 / 花费 → 用卡**（第三期）：上月各卡花费、返现估算、「如果用最优卡能多赚 $X」。
- 手机和电脑：卡片列表一列；推荐结果在手机上纵向三张卡，宽屏横排三栏。

## 9. 与现有模块的关系

- **账单**：还款提醒和记录复用「信用卡」类账单；卡页里显示关联账单的下次到期日。
- **银行导入**：导入批次的账户标签对应到卡（按尾号匹配），用来累计开卡奖励进度、封顶进度、复盘。导入时「这批是哪个账户的」下拉里直接列卡。
- **预算**：不改预算分组；返现估算只在用卡页和回顾里显示。
- **AI 助手**：AI 起草画像走现有 `askText`，用现有的 key 和额度管理。

## 10. 分期

**第一期（卡档案 + 推荐 + 提醒）**：迁移 032 `cards` 表；内置目录 20–30 张；卡的增删改；「用卡」页与快速查询；采购清单 / 补记花费旁的建议；到期 / 年费 / 轮换激活提醒；「创建还款账单」关联。
**第二期（进度 + AI）**：开卡奖励与报销额度进度（从花费 / 导入自动累计）；封顶进度；AI 起草画像；季度轮换日历的「刷新」。
**第三期（复盘）**：按账户的上月复盘、年度返现汇总。

## 11. 待确认的问题

1. 卡画像来源：内置目录 + AI 起草（推荐）还是只手填？AI 起草意味着把卡的产品名发给模型。
2. 积分估值：统一按 1 点 = 1 美分，还是每张卡自己填点值（推荐，航空 / 酒店卡差别大）？
3. 还款提醒：复用账单模块（推荐，不重复做）还是卡模块自带？
4. 持卡人：卡记到人（推荐；以后「你和配偶各自该用哪张」要靠它）还是家庭共用不记人？
5. 你们现在有哪几张卡（发卡行 + 产品名）？目录第一版优先覆盖这些。
