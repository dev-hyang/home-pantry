# 花费分类重整（2026-10-24）

## 问题

分类来自六套（日常储备、装备、房屋、车辆、外出与服务、旅行出行）再加账单和一次性账单，有几处互相重合，记账时不知道选哪个：

- 「旅行出行」是**场景**，「外出就餐 / 燃油 / 门票」是**种类**：同一顿饭在家附近选外出就餐、在旅途中选旅行·餐饮，统计里分到两组；而旅行页本来已经靠「【行程】」标签汇总，不需要靠分类。
- 装备里的「出行户外」和「旅行出行」名字都带「出行」。
- 「网购 / 综合购物」是渠道不是种类，放在「外出与服务」里更乱。
- 五个「学习」：课程 / 课外班账单 / 学费账单 / 图书装备 / 学习文具。
- 三个「宠物」。
- 政府证件、罚单、报税软件、律师费、房产交易费用没处放。
- 买房卖房、买车整付这种几年一次的巨额支出一混进来，每月占比、预算、趋势全部被拉歪。

## 新结构（每个分类只属于一处）

| 组 | 分类 | 规则 |
|---|---|---|
| 日常储备 | 生鲜 / 冷冻 / 干货 / 饮品 / 日用 / 母婴 / 药品保健 / 文具 / **宠物用品** / 超市杂货（未细分） | 买回家、会用完 |
| 装备 | 家居 / 厨房 / 衣物 / **户外与行李** / 汽车装备 / 工具 / 园艺 / 数码 / 图书 | 买回家、长期用 |
| 房屋 | 耗材 / 维修保养 / 装修项目（+ 账单里的草坪保洁等） | |
| 车与交通 | 车辆保养 / 燃油充电 / **交通出行**（新：打车、公交地铁、停车、过路费的一次性花费） | |
| **餐饮外食**（新组） | 外出就餐 / 外卖 / 咖啡 | 单独做预算 |
| **休闲与个人**（原「外出与服务」改名） | 娱乐门票活动 / 美容理发 / 健身 / 礼物 / 课程培训 | 买的是体验 |
| **政务与手续**（新组） | **证件 / 罚单 / 政府收费 / 报税软件**（新） / 银行手续费利息 / 邮寄 / 法律税务（一次性账单） | |
| 旅行专属 | 机票 / 船票邮轮 / 长途车票 / 住宿 / 租车 / 旅行团 / 其他 | 不出门旅行就不会有的；旅途中吃饭、加油、门票记普通分类 + 行程标签 |
| 待细分 / 其他 | 综合购物（待细分）/ 其他生活开销 | 统计里归「其他」，有空再细分 |
| **资本性支出**（新组） | 房产交易（房款 / 首付 / 律师 / 中介 / Title / 过户税 / 检查）/ 买车整付 / 投资转入 / 其他 | **默认不进统计图和预算**；花费页有「含资本性支出」开关 |
| 账单 / 医疗 / 宠物医疗 | 不变 | |

常见问题怎么归：报税软件（TurboTax）→ 证件 / 罚单 / 政府收费 / 报税软件；出生证、驾照、护照 → 同上；罚单 → 同上；装修工程的许可 / 检验费 → 一次性账单·装修项目（小类「许可 / 检验」）；买房的律师、中介、Title、过户税 → 资本性支出·房产交易，名称写「【Elm St 买房】律师费」可以按交易汇总；卖房 / 卖车的收入不记花费（这里只记支出），成交价记在 房屋 → 交易 的交割页。

## 迁移与数据

- 大多数改动只是改名 / 换组，id 不变，数据不动。
- 合并三个旧 id：`travel_dining → life_dining`、`travel_fuel → vehicle_fuel`、`travel_tickets → life_fun`。应用读花费时按别名表（data.js `CAT_ALIAS`）自动换，所以不跑迁移也不会乱；`supabase/migrations/035_category_merge.sql` 把数据库里的旧 id 改干净。
- 一次性「旅行」账单的小类去掉餐饮 / 燃油 / 门票；已有账单里这三个小类生成花费时按别名换。
- 预算：「外出与服务」组 id 不变（只改名），预算金额保留；新增「餐饮外食」「政务与手续」两组，初始额按过去 6 个月实际。
- 不删任何记录。

# 三级分类与统计口径（2026-10-31，迁移 055）

## 问题

周期账单、一次性账单、投资、房产交易都记成「花费」放在一起算：买一次房、装修一次、转一笔钱去券商，那个月的月均、趋势、预算就全被拉歪；信用卡还款、自己账户之间转账如果也记，会重复计算。

## 做法：不改数据，只加一层「报表规则」

- `purchases.category` 一个都不改写：现有的每个分类 id 都是第三级（叶子）。归到哪个二级 / 一级、算进哪些统计，全在 `js/core/taxonomy.js`（唯一的规则来源）。图表、预算、筛选、记账下拉、数据库筛选参数都从这里读。回滚 = 退回前端代码。
- 新增两列：`purchases.nature`（经济性质，空 = 按分类默认）、`purchases.property_id`（关联房产；账单缴费记的花费自动填账单的房产，迁移里一次性回填）。自建分类多一个 `custom_categories.parent`（挂在哪个二级分类下）。

## 分类树

| 一级 | 二级 → 叶子 |
|---|---|
| 生活消费 | 餐饮（生鲜 / 冷冻 / 干货 / 饮品 / 超市杂货 / 外出就餐）· 交通（燃油 / 打车停车 / 车辆保养 / 汽车装备 / 汽车养护 / 车险 / 牌照 / 停车 / 通行费 / 买车整付）· 水电网通讯 · 医疗健康 · 孩子与教育 · 购物日用 · 旅行 · 休闲娱乐 · 个人与家庭 · 宠物 · 其他 |
| 房产住房 | 房贷 · 房租 · 房产税 · 房屋保险 · HOA · 维护与服务（房屋耗材、设备维修保养、草坪保洁除虫安防泳池仓储）· 装修改善（project）· 房产交易（capital_home） |
| 投资理财 | 投资储蓄（capital_invest） |
| 财务及其他 | 税务 · 贷款利息与手续费 · 保险（人寿 / 其他）· 政务手续（证件罚单、邮寄、法律税务）· 捐款奉献 · 工作与进修（含 life_edu = 成人课程培训）· 其他资本性 |
| 转账 | 信用卡还款（bill_credit_card）· 账户间转账 · 投资账户内部转换 |

不认识的 id、没挂父级的自建分类：储藏 → 餐饮，装备 → 购物日用，房屋耗材 → 维护与服务，其余 → 生活消费 · 其他。

## 经济性质与统计桶

性质：日常消费 / 资本性 / 投资 / 融资还本 / 转账。默认：买车整付、装修项目、房产交易、其他资本性 = 资本性；投资转入 = 投资；转账类 = 转账；其余日常消费。以前的「大件」门槛现在只是记一笔时问一句「金额较大，标为资本性支出？」。

每一笔只落进一个桶（`bucketOf`）：转账 → 不算；资本性 → 资本性；投资 → 投资；融资 → 财务；其余按一级分类 → 日常 / 住房 / 财务。

- **日常生活成本** = 日常桶（生活消费 × 日常消费）；和「含住房」（再加住房桶）一起显示，给月均、中位数（只用过完的月份）、均摊（账单按每月折算代替缴费那个月的实际金额）。
- **现金流出** = 除转账以外全部。**投资 / 资本性** = 按性质。
- 预算：固定账单一组，其余按二级分类分组；转账、资本性、投资不进预算。旧的预算分组键（日常储备、大件家电…）读的时候换算成二级分类，存储不改，保存时写新键。

## 统计数据从哪来

概览、分类、商店、账单概览的速览不再把花费整表读进浏览器：数据库 `spend_rollup` / `spend_rollup_store` 按 月 × 分类 × 性质 × 房产 × 币种（商店版加商店）聚合好（含医疗等事件型账单的付款），前端 `js/stats/report.js` 按分类树再汇总。明细仍是 054 的服务器分页，多了分类树、性质、房产筛选；转账照样列出（带标记），合计不算。
