# 净资产（财务 P3）设计

> 2026-11，迁移 059。相关：[design-finance-ia.md](design-finance-ia.md)（P1 信息架构和分期）、[design-debt-lending.md](design-debt-lending.md)（P2 借贷、摊还余额、价格旁表）、[design-income-ledger.md](design-income-ledger.md)（收支总览的口径）。

## 1. 问题与成功标准

**问题**
- 只有现金流（收入、消费），看不到「家里到底有多少钱」：账户余额、房子和车值多少、还欠多少，没有地方记，也没有历史。
- 资产页和借贷页的「估值 / 余额 / 净值」一直是「P3」占位。
- 信用卡欠款在 P2 里留着没做（循环额度没有本金和期限）。
- 没法回答设计里的两个问题：**财富在增长吗**（净资产每月变化）和**日子过得怎么样**（消费），以及增长是攒出来的还是涨出来的。

**成功标准**
- 财务 → 分析 → 净资产：净资产、总资产、总负债、比上月；资产 / 负债按分类排行（带占比，不用饼图）；按月走势；财富增长 vs 消费；每处房产 / 车辆的净值；数据新鲜度提示。
- 资产页、卡与账户里可以就地更新余额 / 估值，带历史。
- 同一笔钱只算一次（贷款不和「贷款」账户重复，房产估值不和购入价重复）；关系按 id，不复制数据。
- 每月自动留一个快照，不需要定时任务；也能手动保存、重建过去某月。
- 只有家主 / 有财务权限的人看得到（界面 + 数据库）；所有旧网址照常打开。

## 2. 数据模型（迁移 059）

```
account_balances（余额历史）              asset_valuations（估值历史）               net_worth_snapshots（每月快照）
 id, household_id                          id, household_id                           id, household_id
 card_id → cards（级联删）                  property_id → properties（级联删）  ┐恰好一个   month 'YYYY-MM'（unique per household）
 as_of date, balance numeric(14,2)          asset_id → assets（级联删）         ┘          totals jsonb（13 个分类）
 currency, source manual|import, notes      as_of, value ≥ 0, currency                  assets_total, liabilities_total, net_worth
 unique (card_id, as_of)                    source manual|estimate, notes              currency, source auto|manual, meta jsonb
                                            unique (property_id, as_of) / (asset_id, as_of)（部分索引）
```

- **最新一行 = 当前值**：余额、估值都是历史表，不在 `cards` / `properties` / `assets` 上加「当前值」列——当前值是推出来的，不会和历史对不上。
- 同一账户 / 资产同一天只有一行：再记一次就是改那一天（余额走 `upsert onConflict card_id,as_of`；估值是部分唯一索引，PostgREST 的 onConflict 用不上，前端先在内存里找同一天的行带 id 去改）。
- 信用卡、「贷款」账户的余额 = **欠款**（正数）。资产账户透支记负数。
- **礼品卡不进余额表、不算净资产**：`cards.balance` 照旧是面值，余额 = 面值 − 记在卡上的花费（迁移 040），要读 `card_totals` 聚合；金额小、很快花掉，而且买礼品卡那笔钱已经记成了花费，再算成资产会让「花费」和「资产」各算一次。借记卡也不记（钱在它扣款的支票账户里）。
- 行级安全：三张表都是 `my_finance_household_ids()` + restrictive `finance_gate`（和 058 的借贷一样）；触发器 `enforce_nw_refs` 保证引用的卡 / 房产 / 设备是同一个家庭的（先按 `tg_table_name` 分支，只读本表的列）。实时同步：三张表都加进 `supabase_realtime`。
- 没有 RPC：全是小表（每个账户每次更新一行、每处资产每次估值一行、每月一行），启动时整表读进内存（`pageAll` 分页，不会被 1000 行截断），在前端算。按「SQL / RPC 只给要扫大明细表的统计」的原则，这里不需要。

## 3. 公式

**净资产 = 资产合计 − 负债合计**（`js/stats/net-worth.js`，纯函数，有测试）。

| 分类（totals 的键） | 来源 |
|---|---|
| `cash` 现金与储蓄 | 支票、储蓄、现金、电子钱包账户的最新余额 |
| `investments` 投资账户 | 券商账户 |
| `retirement` 退休账户 | 401K / IRA |
| `hsa` | HSA |
| `properties` 房产 | 持有中的房产：最新估值；没有估值 → 购入价（`property_financials`，标「按购入价」） |
| `vehicles` 车辆 | 拥有的车（持有 / 贷款中）：最新估值；没有估值 → **不算**（车贬值快，购入价会高估），列为「未估值」 |
| `other_assets` 其他资产 | 估过值的设备（钢琴之类）；没估值的家电不当资产 |
| `receivables` 应收 | 借出（`direction = receivable`）贷款的未还本金 |
| `mortgage` 房贷（含 HELOC） | 借入贷款，类型 mortgage / heloc / home_equity |
| `auto_loans` 车贷 | auto_loan |
| `other_loans` 其他贷款 | 学生贷款、个人贷款、信用额度、其他；**没有对应贷款记录的「贷款」账户**的余额 |
| `credit_cards` 信用卡欠款 | 信用卡的最新余额（欠款） |
| `other_liabilities` 其他负债 | 向亲友借的钱（personal_lending + payable）、资产账户透支 |

- **贷款余额** = P2 的摊还余额（`amortization.outstanding`：起点 ± 之后的流水）。不知道起点（没填本金、没有某天的余额、没有放款记录）→ 不算，列在新鲜度里。
- **已结清**（paid_off / written_off / closed）的贷款不算。
- **持有**：房产 —— 不是租住 / 看房 / 已退租；买入日之后、卖出日之前（没日期看状态）。车辆 —— 不是选购中 / 租赁 / 已归还（租的车不是资产）；买入日之后、卖出 / 归还日之前。
- **每处资产的净值** = 市值 − 挂在它上面（`debt_accounts.property_id / asset_id`）的借入贷款的未还本金。没估值 → 净值「—」。
- **多币种**：只算家庭币种（`Units.region.currency`）。其他币种的余额、估值、贷款单列「其他币种（不算进净资产）」，不换算（没有汇率来源，换算会让数字每天跳）。

### 不重复的规则
1. **贷款 vs「贷款」账户**：一笔贷款的 `lender_card_id` 指向一个 kind = loan 的账户时，只算贷款（摊还余额是唯一来源），那个账户上记的余额不算（资产页写「余额按借贷里的贷款算」，不给更新余额的表单）。没挂贷款的「贷款」账户按账户余额算 —— 适合不想建摊还表的小额贷款。
2. **房产估值 vs 购入价**：有估值就不用购入价，二者只取其一。
3. **信用卡**：P2 没把信用卡账单转成贷款（循环额度），所以信用卡欠款只有余额表这一个来源，还款仍是「转账」，不算花费，也不会和负债重复。
4. **Escrow**：贷款方代管的 Escrow 余额不记（没有数据来源），不算资产。
5. **礼品卡**：见 §2，不算。

## 4. 快照

- **自动**：有财务权限的人打开「财务」任何一页（`render` 时调 `maybeAutoSnapshot`），本月还没有快照 → 在内存里算好写一行（source = auto）；本月里再打开、数字变了 → 更新这一行（所以 auto 快照 ≈ 本月最后一次打开时的值）。全家什么都没登记（没有余额、房产、贷款）时不写。写失败（比如权限刚被收回）这次打开不再重试。
- 云端写法：`upsert … ignoreDuplicates` 只在没有时新建；已有的只 `update … where source = 'auto'`，别的设备刚手动保存的不会被盖掉。
- **手动**：「保存本月快照」覆盖本月（source = manual），之后自动不再动它。
- **重建过去某月**：只用那个月月底以前的数据——余额 / 估值取那天及以前最新的一行；贷款余额只算那天及以前的流水；房产 / 车辆按买卖日期判断；在那天之后还有流水的已结清贷款仍算（那时还没还完）；那时已停用的账户不算。写 source = manual、`meta.rebuilt = true`。
- 走势用快照；本月的点用实时计算替换，KPI 和曲线一致。**比上月** = 本月实时 − 上个月的快照；上个月没有快照显示「—」，不拿更早的月份冒充环比。
- `meta` 记计算说明：截至日期、按购入价的个数、未估值个数、过期 / 缺余额的账户数、未知余额的贷款数、其他币种项数、是否重建。

## 5. 财富增长 vs 消费

每个有快照的月份一行：**净资产变化**（和上个月快照比）、**收入**（认定收入）、**消费**（日常 + 住房，和收支总览同一口径：`report.js` 的 `aggregate` / `incAggregate`，`spend_rollup` / `inc_rollup` 已有的按月聚合缓存，不新增查询）、**储蓄** = 收入 − 消费、**其他变化** = 净资产变化 − 储蓄（市值涨跌、估值更新、没记账的现金流）。用表格不用柱图：有负数、读屏按表读。

## 6. 界面

- **财务 → 分析 → 净资产**（`#/bills/networth`；别名 `#/finance/net-worth`、`#/finance/networth`、`#/bills/net-worth`、`#/bills/nw`）：KPI 四格；数据新鲜度（余额超过 60 天标「需要更新」并链到那个账户、没记过余额的账户、按购入价 / 未估值的资产、不知道余额的贷款）；资产 / 负债构成（`Charts.hbars` 排行条带 %）；走势（`Charts.line`，近 12 / 24 个月 / 全部，下面有数据表）；财富增长 vs 消费；资产净值表（每行链回房屋 / 车辆记录，贷款链到借贷详情）；其他币种；每月快照（折叠：保存本月、重建某月、列表 5 条一页、删除要点两次）。
- **资产页**：房产 / 车辆多两格「市值」「净值」，下面是折叠的「估值：… 更新估值」（日期、市值、来源、备注；历史 5 条一页）；账户区改为「账户与余额」（含信用卡），每个账户显示最新余额 / 日期 / 需要更新，折叠的「更新余额」+ 历史；KPI 加「余额合计」和「净资产」（点进净资产页）。
- **卡与账户**：编辑一张卡 / 一个账户时，表单下面是「余额 / 欠款：… 更新余额」+ 历史（只有财务权限；借记卡、礼品卡没有）。
- **借贷**：贷款卡片的「净值 P3」换成关联资产的净值（链到净资产页；没估值链到资产页）。
- **收支总览**：KPI 下面一张小卡片「📈 净资产 $… · 比上月 …」，点进净资产页。
- 手机：表格放在可横滑、可键盘聚焦的 `role=region` 里，≤ 640px 隐藏「其他变化」列；按钮、折叠标题、输入框都 ≥ 44px；折叠的开合在重画后保持（`state.nwUi`）。

## 7. 权限

| | 家主 / 有财务权限 | 没有财务权限 |
|---|---|---|
| 净资产页（目录、快捷操作、网址） | ✓ | ✗（`FINANCE_HIDDEN_SUBS` 含 `networth`，别名也挡） |
| 资产页、借贷里的估值 / 余额 / 净值 | ✓ | ✗（整页本来就挡） |
| 卡与账户里的余额历史 | ✓ | 不显示（卡页本身只读可看） |
| 收支总览的净资产卡片 | ✓ | ✗（收入页整页挡） |
| `account_balances` / `asset_valuations` / `net_worth_snapshots` | 读写 | 数据库读写都不行（RLS） |

## 8. 局限 / 以后

- **重建过去**：账户在那个月以前没记余额就不算；房产 / 车辆的状态历史没有存（只用买卖日期 + 现在的状态）；从「某天的余额」开始记的贷款，重建更早的月份时余额按那天的余额算（偏低估更早的负债）。
- 没有自动拿余额（Plaid 之类）、自动估值（Zillow / KBB API）：手动填，60 天提醒。`source = import` 预留给以后从对账单导入余额。
- 多币种不换算。
- 走势图的纵轴从 0 开始，净资产为负的月份画在 0 以下（准确数字看图下的表）。
- 快照只存合计，不存每个账户的明细；要看某个账户的历史看它自己的余额历史。
