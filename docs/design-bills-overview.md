## 1. 问题与成功标准

**问题**
1. 现在有**两个都叫「概览」的页面**：`#/bills/overview`（`viewBillsHome`，周期性 + 一次性的入口）和周期性账单的「概览」标签（`viewBillsOverview`）。内容大幅重叠（未来 30 天、本月账单、要处理的账单），用户分不清自己在哪一层。
2. 统计没有**说清范围**：「未来 30 天要交」「每月固定支出」「一次性未结」三个数字时间口径各不相同，页面上也不写。
3. 概览里夹了 **「花费速览」**（花费统计），和「账单」不是一回事，花费有自己的页面。
4. **没有一个「所有账单」的行记录页**：周期性账单的清单只含周期性，一次性账单的清单只含一次性；想问「这个月所有账单我还欠多少、哪些最先到期」得到处翻。
5. 数字**不能点进去看明细**：KPI 只是展示，不是入口。
6. 看不到**按资产**（房子、车子、设备、医疗、工程）的账单：只有一个房产下拉，车辆靠名字匹配，设备和工程没有统一维度。

**成功标准**（用户视角，可验收）
- 打开 财务 → 账单概览，**默认看全部资产**（所有房产、车辆、医疗、工程等的账单合在一起），页面上明确写出「统计范围：本月（2026-11）· 全部资产」。
- 概览上每张卡片都能点，落到「全部账单」页，且那一页的筛选**正好等于卡片上的口径**（卡片写 5 笔 $1,200，点进去列表就是这 5 笔，合计 $1,200）。
- 「全部账单」页：有搜索、有筛选（至少含资产）、默认**离到期近的在前**。
- 概览里没有「花费速览」，整页只讲账单。
- 旧网址、书签、今日页 / 提醒的链接照旧能打开。

## 3. 信息架构：页面地图

```
财务 (#/bills)
└─ 分析
   └─ 账单概览   #/bills/overview            ← 本次重构的主页面（dashboard）
        ├─ 全部账单   #/bills/all             ← 新：所有账单的行记录页（所有卡片的落点）
        │     └─ 单张账单  #/bill/<id> 或 #/bills/onetime?bill=<id>   （已有）
        ├─ 周期性账单 #/bills/recurring       （已有：概览 / 清单 / 记录）
        └─ 一次性账单 #/bills/onetime         （已有：概览 / 账单 / 年度报表）
```

**三个入口各管什么**（避免再次混淆，页面顶上用一句话说明）

| 页面 | 回答的问题 | 单位 |
|---|---|---|
| 账单概览（dashboard） | 「这段时间我总共要交多少、交了多少、哪些要紧？」 | 汇总数字 |
| **全部账单**（新） | 「具体是哪几笔？谁先到期？」 | **一行 = 一期账单**（一次到期） |
| 周期性账单 → 清单 | 「我设了哪些周期性账单？改设置、开关自动扣款」 | 一行 = 一个账单**项目** |
| 一次性账单 → 账单 | 「这张医疗 / 工程账单的明细、分次付款」 | 一行 = 一张账单 |

要点：「全部账单」是**按期**的视图（电费 11 月一行、12 月又一行），清单是**按项目**的管理视图。这是和现有清单最大的区别，也是需要新写「账单实例」逻辑的原因（§5）。

## 4. 统计范围（时间）— 回答「是以什么时间范围？」

**建议：默认「本月」，且可切换；页面上始终显示当前范围。**

- 范围选项：`本月`（默认）· `上月` · `下月` · `未来 30 天` · `近 3 个月` · `今年` · `自定义（按月）`。
- 口径：一期账单**按它的到期日（`due_on`）落在范围内**计入。一次性账单没有到期日的，按账单日 / 就诊日。
- **逾期永远计入**，不受范围限制：8 月欠的没交，选「本月」时也要在「逾期」卡里出现，否则最危险的一类会消失。卡片上写明「含上月以前逾期 N 笔」。
- 范围条放在页面顶部（和花费 / 收入一样的样式），但**用独立的本机存储键**（建议 `hmh-bills-range`，默认 `m`），不改花费 / 收入共用的 `hmh-fin-range`（默认近 12 个月）。
  - `time-range.js` 目前只有过去的范围，要给账单加「下月」「未来 30 天」两个选项（只加在账单用的那一份选项里，不动花费收入的下拉）。
- 「全部资产」是资产筛选的默认值，不是时间的默认值；两个条件互不影响。

## 5. 六张卡片：定义、口径、落点

参考你给的图（Total Bills / Overdue / Paid / Next Bill Due / Due Soon / Remaining Balance）。

| 卡片 | 显示 | 口径（范围内，除非注明） | 点击去 |
|---|---|---|---|
| **全部账单 Total Bills** | `12 笔 · $5,860.00` | 到期日在范围内的所有账单期（已缴 + 未缴）的**应付金额**合计；逾期的也算在内 | `all?range=…`（不加状态） |
| **逾期 Overdue** | `3 笔 · $605.00`，红 / 琥珀 | 已过到期日 + 宽限天数仍未缴清，**不限范围** | `all?status=overdue` |
| **已缴 Paid** | `9 笔 · $4,830.00` | 范围内已缴清（含部分已付里已付的部分只算在「已缴金额」，笔数只数已结清的） | `all?status=paid&range=…` |
| **下一笔到期 Next Due** | `11/22 电费 · 5 天后` | 今天起最近一笔**未缴**，不限范围；金额也显示 | 打开那张账单；卡片底部「看全部待缴」→ `all?status=unpaid` |
| **即将到期 Due Soon** | `2 笔 · $345.00` | 未缴且到期日在 **7 天内**（和现有提醒窗口 `reminder_days` 默认 [7,1] 对齐）| `all?status=soon` |
| **剩余待缴 Remaining** | `$1,030.00`，蓝 | 范围内未缴清的**余额**合计（含逾期）；= 应付 − 已缴 | `all?status=unpaid&range=…` |

**数字必须自洽**：`应付合计 = 已缴 + 剩余`；点进去的列表合计 = 卡片金额。这条做成测试（见 §9）。

**计数规则（容易出错，要写测试）**
- **账单实例（instance）**：周期性账单按频率展开成范围内的每一期（月付 3 个月 = 3 期；半年付 / 年付 / 双周 / 月末 31 日截断 / `due_dates` 列表都要处理，复用 `logic.js` 现有「下一次到期」规则）。一次性账单 = 一期。
- **不凭空造逾期**：展开只从「这条账单第一次出现」开始（`created_at` 或最早缴费记录），之前的月份不算；刚建的账单不会冒出一串历史逾期。
- **已缴判定**：该期有 `status != skipped` 的缴费记录（周期性按 `due_on` 对上）；一次性看 `balance ≤ 0`；`skipped` 不计入也不算逾期。
- **自动扣款**：到期日后无记录 → 状态「待核对」（不是逾期），金额计入剩余；核对后写缴费记录变已缴。
- **Escrow 代缴**（`pay_channel = escrow`，房产税 / 保险由房贷代付）：不是你另外掏的现金 → **不计入**应付 / 剩余，概览底部单独一行「Escrow 代缴 N 笔 · $X（不计入上面的数字）」，保持和现有 Escrow 面板一致。
- **应收**（`direction = receivable`，房东租金）：不是账单支出，**排除**；以后需要再单做「应收」卡。
- **币种**：只汇总当前地区币种；其他币种另起一行提示「另有 N 笔非 USD 账单未计入」（沿用现有做法，不静默丢）。
- **变动金额**：没缴之前用 `est`（最近 6 次均值）估；估算的金额在行内标「估」，卡片金额旁小字注明「含估算」。
- **私密账单**：医疗 / 法律默认私密（`visibility = private`）。**没有权限的人，笔数和金额都不能含这些**（否则合计会泄露）；有权限的人在行上看到 🔒。统计口径在「读数据那一步」就过滤，不是前端藏行。

## 6. 资产维度 — 回答「筛选器至少要包含资产」

「资产」下拉分组（默认「全部资产」）：

```
全部资产（默认）
── 房产 ──   🏠 家（每套房产一项；已卖出 / 退租的在最后一组，沿用现有规则）
── 车辆 ──   🚗 全部车辆 · 每辆车一项（需要 §6.2 的 asset_id；之前先用「全部车辆」）
── 设备 ──   🔧 全部设备 · 每件一项（同上，需要 asset_id）
── 家人 ──   🏥 医疗（按患者：每位家人一项）· 🐾 宠物
── 项目 ──   🔨 装修 / 工程 · ⚖️ 法律 / 税务 · 🧳 旅行
── 其他 ──   🧾 家庭通用（不挂任何资产：手机、订阅、保险…）
```

### 6.1 一期（不动数据库）：「资产归属」由现有字段推出
```
assetOf(row):
  row.property_id            → 房产（那一套）
  一次性 kind = medical/pet  → 家人 / 宠物（patient）
  一次性 kind = project      → 项目·装修（有 property_id 则同时归房产，筛「房产」和筛「项目」都能找到）
  一次性 kind = legal/travel → 项目·法律 / 旅行
  周期性 category ∈ {insurance_auto, car_loan, vehicle_reg, toll, parking} → 车辆（笼统：全部车辆）
  其余                       → 家庭通用
```
局限（要如实告诉你）：**车辆只能到「全部车辆」这一档，分不到具体哪辆车**；设备完全没有。

### 6.2 数据库迁移（已提前，放在 home-pantry，不是 baby-log）

- **已有** `076_bills_recurring_asset.sql`：`bills_recurring.asset_id`（只指向车辆，可空，车被删时置空，触发器校验同一家庭）。

## 12. 风险与取舍

- **「按期」展开的正确性**是最大风险：展开错了，逾期数会吓人（或漏）。所以 ② 单独成版、测试先行，上线后概览里保留「怎么算的」说明链接。
- **两个「概览」+ 清单 + 全部账单**四个入口并存期间会有认知负担；靠页面顶部一句话说明 + ⑤ 的瘦身缓解。
- **范围口径**（到期日 vs 付款日）选了「到期日」：好处是和「要交多少」一致；代价是「本月实际付出去多少现金」要看花费页，两者可能不等。页面上不混用「花费」这个词。
- **估算金额**（变动账单）会让合计有偏差，已通过「含估算」标注降低误解，但不能消除。

## 13. 账单期怎么「生成」——回应删除 / 重算的顾虑

**核心做法：不预先生成账单行。** 每一期（如 2026-12 的电费）是**打开页面时在内存里从账单规则算出来的**，数据库里只存两样真正发生过的东西：账单规则（`bills_recurring`）和缴费记录（`bills_recurring_payments`）。所以：

- **算错了怎么办 / 能不能「只重算某一期」**：没有「已生成的期」可删，也不需要整批重新生成。改了规则（金额、频率、到期日）→ **所有还没缴的期立刻按新规则重算**；已缴的期保持原样（它有自己的缴费记录和金额）。想只动某一期：
  - 这一期不用交 → 在这一期上点「跳过」（写一条 `skipped` 记录，可撤销 = 删掉这条）；
  - 这一期金额不同 → 记缴费时直接填实际金额，不影响别的期；
  - 想改还没缴的某一期的预估 → 在这一期上「调整本期金额」（只改这一期，不改规则；实现上写一条带金额的待缴记录，可撤销）。
- **记录错了怎么删**：在账单的缴费记录里删那一条（`deleteBillPay`，已有）：会**一起删掉它写进花费的那条 `purchases`**，所以花费统计里也同步消失，下一期自动退回待缴。一次性账单的分次付款同理。版本④的「全部账单」行上提供同样的「撤销这笔缴费」，不用绕到账单详情。
- **一次展开多长**：只展开**当前范围**那几个月（默认本月，最长设上限 36 期），不是一次生成一整年；换范围就重新算，没有任何持久化副作用。刚建的账单不往过去展开（§5）。

**金额：估算 vs 真实**（电费、燃气等变动金额）
- 未缴的期显示「估」（最近 6 次均值），卡片小字「含估算 N 笔」。
- 记缴费时填**真实金额**：该期立刻变成真实值，合计同步；记缴费表单顶部提示「本期预估 $X」，并提供一个**可选的**「用这次的金额更新常规金额」勾选（只对固定金额类建议默认勾上，变动类不动，因为变动类本来按均值估）。
- 不强求每月手工录入账单：没录就一直是估算（带「估」标），不会把估算当成真实数字去对账。

## 14. 新账单表单与 AI 扫描（版本⑥⑦的设计要点，开工前再细化）

## 15. 版本①–⑥ 实现中做的决定（请你看一下，不对的告诉我）

这些是我在做的时候按「保守、可回退」自己定的，没有再打断你。**列出来请你确认或改**：

1. **逾期封顶**：同一张周期性账单，没缴的逾期期最多显示最近 **3 期**，更早的不展开，只在页面提示「另有 N 期太久远没有展开」。原因：自动扣款账单常常没人记缴费记录，`next_due_on` 停在很久以前，会冒出一长串逾期。要放宽 / 改成别的数？
2. **自动扣款过了到期日没记录** = 「待核对」，不算逾期，但计入「剩余待缴」；点「已核对」才变已缴。
3. **一次性账单没填到期日**：归月时按「账单日 → 就诊 / 服务日」；一个日期都没有的不会出现在某个月里（只有逾期时才显示，而没有到期日的不会逾期）。要不要给没日期的单独一组「未定日期」？

## 16. 引导式创建账单（设计，待你确认后分版本实现）

> 2026-11-17。起因：现在新建一张周期性账单，整页铺开 30 多个字段（4 个分区全部展开），第一次用的人会被吓到；AI 扫描之后还要自己再点保存；保存后回到来路页，看不到刚建的这张账单长什么样。
> **这一节的目的：让创建账单变成一个被引导的、轻松的过程——一次只回答一两个问题，其余用聪明的默认值，剩下的随时在详情页补。**

### 16.1 问题与成功标准

**问题**
1. **字段太多**：新建表单一次摆出名称、分类、房产、资产、付款方、账号尾号、登录提示、缴费链接、缴费方式、账单来源、金额类型、金额、币种、频率、到期日、宽限、结束日期、提醒、滞纳金、付款账户、自动扣款、卡有效期、负责人、必要、启用、备注……大多数人只需要其中 5–6 个。
2. **没有「完成」的感觉**：保存后回到来路页（清单 / 概览），不知道新账单建成了什么样。
3. **详情页要点进去才看得到内容**：现在的账单详情是「枢纽」（摘要 + 一排分区入口），每一块的内容要点进去才看到；房屋资料页就好得多：每个分区一张卡片，内容直接可见，旁边一个「编辑」。
4. **AI 扫描后还要手动保存**：用户已经拍了照，却还要在表单里核对一遍再点保存，扫描的好处打了折扣。

**成功标准（用户视角，可验收）**
- 手动创建一张最常见的账单（例如电费）：**≤ 4 步有输入、≤ 6 个字段、1 分钟内完成**；其余字段一个都不用碰。
- 每一步**只问一两件事**，每步都有一句话说明为什么问；任何一步都能「上一步」、都不会丢已经填的内容。
- 完成后**一定落在这张账单的详情页**，能看到它建成了什么样、还有哪些没填，并且每一块都能单独编辑。
- AI 扫描创建：拍照 → **直接建好 → 进入详情页查看**，不再经过表单；识别错了能逐块改或一键撤销。
- 老手想一页填完，仍然可以（整页表单保留，入口清楚）。

### 16.2 我的思考（为什么这样设计）

- **渐进披露**：必须知道的先问，其余的给默认值、放到详情页「补充」。字段不是消失了，是**从「创建时必须面对」变成「想补的时候再补」**。向导里出现的字段，只选「没有它这张账单就没法工作」的：名称 / 分类（要分组）、多久一次 + 到期日（要算下次到期）、怎么付（决定提醒的是「去缴费」还是「去核对」）。金额可以先不填（变动账单本来就按记录估）。
- **智能默认**：选了分类就带出默认频率、提醒天数、是否通常自动扣款、建议名称（`data/bills.js` 的模板已有这些）。用户多数时候只是点「下一步」。
- **一屏一个问题**：手机上最舒服的形态，也是笔记本上不需要「两套设计」的做法——同一个向导，笔记本只是居中限宽（≈ 640px），手机占满。
- **向导 vs 整页表单是两个层次**：向导 = 创建；详情页 = 查看 + 逐块编辑。**编辑不走向导**（已存在的账单用现有的单分区编辑页，已经做好了）。
- **AI 路径和手动路径是两条线**：手动 = 向导（你在做决定）；AI = 它替你做完，你来验收（所以直接到详情页）。验收的工具是详情页上的「AI 识别创建」提示条 + 逐块编辑 + 撤销，而不是一张你必须逐项确认的表单。
- **不引入数据库改动**：向导只是换一种方式收集同一批字段，保存仍是 `Store.saveBill`。唯一的代码前提：`saveBill` 现在新建时不返回新账单的 id（要进详情页就得知道 id），要让它返回。

- **去重**：第 1 步点「下一步」时，如果已有同名 / 同付款方同分类的在用账单，先就地提示「已有『ComEd 电费』，要打开它吗？」（沿用现有的疑似重复判断）。
- **返回键 = 上一步**（步骤放在网址 `?step=2`，所以手机返回手势、浏览器后退都按预期走；刷新停在当前步，输入保留在页面状态里）。
- **完成**：`saveBill` → 拿到新 id → 直接 `go(#/bill/<id>)`，详情页顶部出现「已创建」提示条。

**一次性账单向导（版本⑩d，4–5 步）**：① 哪一类（医疗 / 宠物 / 法律税务 / 装修工程 / 旅行，大卡片）→ ② 谁收的、关于谁或什么项目（机构、患者 / 项目名）→ ③ 多少钱、什么时候（总额；医疗 / 宠物多问保险已付；账单日、到期日）→ ④ 挂靠与可见范围（房产 / 资产；医疗和法律默认「仅自己和家主可见」，用一句话说明）→ ⑤ 确认。完成后进入这张账单的详情页。

**老手入口**：选类型页和向导每一步顶部都有「我想一次填完」→ 现有的整页表单，不删。

### 16.6 AI 扫描创建：直接进详情页验收

- 选类型页的「📷 扫描信件 / 账单」→（发送前确认，沿用）→ AI 读出 → `routeScan` 判断类型 → **直接创建这张账单** → 跳到它的详情页。
- **创建条件**：周期性需要名称 + 能算出下次到期日（`next_due_on` 或频率 + 每月几号）；一次性需要机构名（provider）。**缺必填项就不硬建**：退回向导，把已识别的填进对应步骤，从缺的那一步开始问（「我读到了大部分，还差这一项」）。
- **详情页顶部「✨ AI 识别创建」提示条**：列出读到了哪几项（推测的标黄带「？」），说明「看一眼就行：不对的点对应分区的『编辑』改；整张读错了点『撤销创建』」。**撤销创建** = 删除这张账单（要确认；不留下缴费记录 / 花费，因为刚建的还没有）。
- **疑似重复**：AI 创建前先查重；已有同名 / 同付款方同分类的在用账单 → 不静默再建一张，提示「已有 ComEd 电费。仍然新建，还是打开已有的？」
- **隐私**（不变）：发图前确认；医疗 / 法律不读诊断和治疗代码；账号只取后 4 位；医疗 / 法律的新账单默认仅自己和家主可见；图片不保存。
- **和 §14 的区别**：§14 写的是「一律由你核对后点保存」。这一节**按你的要求改成「AI 自动创建，到详情页验收，可逐块修改或撤销」**——风险由「查重 + 缺必填不硬建 + 一键撤销 + 详情页提示条」兜住。表单上原有的「📷 拍账单」（在表单页里拍）不变，仍然是「填进表单，由你保存」。

### 16.8 无障碍与响应式

- 步骤条：`aria-current="step"`，文字「第 2 步 / 共 5 步」（不只靠颜色 / 进度条）；每进一步，焦点移到该步标题，并用 `aria-live` 读出步骤名。
- 大图标网格 / 四选一卡片：用真正的 `radio`（键盘方向键可选，读屏读得出选中项），点按区域 ≥ 44px。
- 错误就地提示（`role="alert"`），不弹窗。
- **笔记本（≈ 1280px）**：向导居中限宽 ≈ 640px；详情页卡片两列。**手机（≈ 390px）**：向导单列、底部「上一步 / 下一步」固定在底栏上方（不被右下角「＋」或底部导航挡住）；详情页单列。
- 控件规则照旧：同一步里输入框 / 下拉**同高、同圆角、同边框**，`box-sizing: border-box`，笔记本和手机（含触屏样式）都量。
- 英文界面：所有新文案进 `en.js`；步骤说明用短句。

### 16.10 风险与取舍

- **向导对老手更慢**：保留「我想一次填完」；向导里「下一步」大多数时候就是点一下。
- **AI 自动创建可能读错**：查重 + 缺必填不硬建 + 详情页提示条逐项列出读到了什么 + 一键撤销；仍然不读诊断 / 治疗代码。
- **默认值可能不合适**（比如某地区电费不是月付）：第 5 步摘要把频率 / 到期日 / 付款方式写清楚，每项点一下就回到那一步改。
- **范围很容易膨胀**：向导里只放 §16.5 表里的字段；想加字段，先问「没有它这张账单能不能工作？」能 → 放详情页。
- **不做**：多步骤的「保存草稿」（见下 5）、向导里的附件上传、批量创建（按模板一次建好多条的流程 `#/bills/template` 保持原样）。

### §10 补充：手机上「搜索框被挤窄」的全站检查（2026-11-17，对应 .14 的修复）
- **修法是全站共用的**：所有「搜索 + 筛选」页的工具条都是同一个 `.toolbar`（手机上被公共的紧凑筛选条收成「搜索框 + 筛选 (n) + 清除」），「清除筛选」按钮也是同一个组件（`core/clear-filters.js`），所以 .14 的 CSS（≤ 440px 时「清除筛选」只显示 ✕、44×44）对这些页一起生效，不是只改了账单。
- **390px 下实测的搜索框宽度**（演示数据，把「清除筛选」强制显示，取最挤的情形）：储藏 → 库存 211px、家居耐用品 211px；采购清单 211px；周期性账单清单 211px；一次性账单清单 177px；花费明细 151px；全部账单 185px；对账单「全部流水」313px（这一页的工具条是 `.st-tools`，本来就会换行，搜索框占满一行，清除按钮在下一行，没有被挤）。所有页都没有横向溢出（页面宽 375 / 视口 390）。
- **没法在演示数据里实测的页**（演示库里没有对应数据，页面不渲染工具条）：房屋 → 设备 / 车辆保养记录、收入明细、借贷（资产融资 / 个人借贷 / 还款记录）。读代码确认它们用的都是同一个 `.toolbar` + 同一个 `clearFiltersBtn`，所以规则同样生效；但没有亲眼量过。
