# 房屋维护模块设计（三期）

## 1. 问题与目标

**问题**：对房屋维修不熟悉的家庭，不知道自己家哪些部位要自己维护、多久保养一次、该备哪些耗材，设备坏了也难判断该修还是该换。北美（芝加哥这类有雪季、夏季空调、四季虫害的地区）和中国的房型、设备和物业制度差别很大。

**目标**：在现有“爱家小助手”里加入房屋维护，复用同一个家庭、登录、采购清单和花费统计，不新增入口。

**成功标准**

- 新家庭在 2 分钟内完成房屋资料，并一次加好常用房屋耗材（不需要逐个手动添加）。
- 首页一个列表同时显示储藏和房屋两边需要处理的事。
- 不需要房屋模块的家庭可以关闭它，界面回到只有厨房储藏的样子。
- 房屋耗材和厨房物品共用采购清单、商店统计和年度报表。

## 2. 信息架构

```
底部导航（6 个）
├── 今日      首页：储藏 + 房屋待办合并、临期食材、采购进度、快捷入口
├── 储藏      概览 / 库存 / 菜单
├── 房屋      概览 / 房屋耗材 / 房屋资料   （第二期加：设备档案、季节任务；第三期加：修还是换）
├── 装备      耐用品清单：家居用品、出行户外、汽车装备、工具、园艺工具；只记数量和位置，不提醒补货
├── 采购      三边共用一张清单
└── 我的      统计 / 设置
```

所有页面使用网址路由（`#/house/supplies`、`#/item/<id>` 等）：手机返回手势可用，页面链接可以直接发给家人。表单一律是独立整页，不使用浮动弹窗。

## 3. 数据分层

| 层 | 例子 | 存在哪里 | 提醒依据 | 期次 |
|---|---|---|---|---|
| 房屋耗材 | 炉子滤网、软水盐、融雪盐、电池、捕鼠器、硅胶、机油、玻璃水 | `items`（`house_*` 分类） | 数量、消耗速度（与储藏相同） | 第一期 |

## 4. 房型模板与责任归属（第一期已实现）

两套模板，可在“房屋资料”里随时切换地区：

- **北美**：独栋（SFH）、联排（Townhome）、公寓（Condo）、租住公寓。
- **中国**：电梯公寓（商品房）、多层/老小区、联排/叠拼、独栋别墅。

每个房型包含默认设施（切换房型时自动预选，可再调整）和一张责任归属表。责任归属覆盖 10 个部位：屋顶、外墙、排水槽、门窗、除雪园林、户内暖通、热水器、户内水管、公共管道电梯、排水泵。负责方有六种取值：自己、HOA、房东、物业/维修基金、看章程或合同、通常没有。

例：Condo 的屋顶、外墙、除雪归 HOA，户内暖通和热水器归自己；电梯公寓的外墙、屋面、公共管道归物业（大修动用维修基金），户内归自己。页面明确提示以 HOA 章程、物业合同或租约为准。

## 5. 材料保养（第一期已实现）

| 部位 | 材料 |
|---|---|
| 外墙 | 砖/石材（Masonry）、乙烯基板（Vinyl）、木质、纤维水泥板、灰泥（Stucco）、外墙涂料/真石漆、外墙瓷砖 |
| 屋面 | 沥青瓦、金属、陶瓦/水泥瓦、平屋面防水层 |
| 地面 | 实木、实木复合、强化复合、LVP/SPC、瓷砖、石材、地毯 |

每种材料 2–4 条保养建议，按地区过滤（例如 Vinyl 只在北美出现，真石漆只在中国出现）。周期和寿命标为常见经验值。

## 6. 耗材推荐模板（第一期已实现）

规则写法：`f:设施`、`ext:外墙`、`floor:地面`、`roof:屋面`、`type:房型`、`*`（总是推荐），满足任一条件就推荐。

- “约每 N 天用 1 个”换算成每天用量，复用现有的“即将告罄”提醒。
- 房屋耗材默认提前 14 天提醒，给网购和去五金店留出时间。
- 少货线自动限制为低于初始数量，避免刚加入就报“少货”。
- 已有同名物品的推荐项显示“已有”，不能重复添加。
- 加入后就是普通库存物品，照常增删改查。

## 7. 第二期设计：设备档案、保养记录、季节任务（已实现）

实现说明（与下方设计的差异）：

- 季节任务不建模板表，模板放在前端 `data/house.js`（`SEASONAL_TASKS`，按地区 / 月份 / 设施），数据库只存完成记录 `seasonal_tasks(task_key, period "YYYY-MM")`。连续月份算同一窗口，窗口内勾一次即算完成；12 个月都有的是每月任务。
- 保养费用写入 `purchases` 时用分类 `house_maint`（不在物品分类里），统计并入“房屋维护”；`maintenance_logs.purchase_id` 关联，删记录时一起删。
- 设备类型 `type` 与模板 `ASSET_TYPES` 对应，屋顶寿命按屋面材料取值；默认负责方取自房型责任归属表。
- 设备页路由 `#/asset/<id>`，整页表单，下方带保养记录和“记一笔”表单；`?log=1` 直接定位到该表单。

**`assets` 表**：

| 字段 | 说明 |
|---|---|
| `kind` | `equipment` 设备 / `tool` 工具 |
| `type` | 设备类型，例如 `furnace`、`ac`、`water_heater_tank`、`sump_pump`、`roof`、`hot_tub`、`water_softener`、`boiler`、`wall_boiler`、`fresh_air` |
| 基本信息 | `name`、`location`、`brand`、`model`、`serial` |
| 年份与保修 | `installed_on`、`manufacture_year`、`warranty_until`、`labor_warranty_until` |
| 寿命与周期 | `expected_life_years`（按类型给默认值，可改）、`service_interval_months` |
| 费用与负责方 | `purchase_price`、`replacement_cost_estimate`、`owner`（自己 / HOA / 物业，默认取自责任归属表） |
| 其他 | `notes` |

**`maintenance_logs` 表**：`asset_id`、`done_on`、`kind`（检查 / 保养 / 维修 / 更换）、`cost`、`diy`、`vendor`、`notes`。

- 记一次保养后，自动计算下次保养日期。
- 有费用的记录同时写入 `purchases`，并入“房屋维护”花费统计。

**设备档案模板**：按房屋资料一次生成设备清单。例如勾选了 Furnace，就生成“暖风炉”档案，默认寿命 15–20 年、每年检修一次；用户补充品牌、型号和安装年份。

**季节任务**：按地区和月份推荐，关联设施，完成时打勾并记录。芝加哥模板示例：

- **秋季**：炉子检修、关闭室外水龙头、清理排水槽、测试排水泵、准备融雪盐、封堵鼠洞。
- **冬季**：高效炉进排气口除雪、关注冰坝、极寒天气防冻管。
- **春季**：雨季前测试排水泵和备用电池、空调检修、屋顶冬后检查、地基周边排水坡度。
- **夏季**：换空调滤网、地下室除湿、清除积水防蚊。
- **全年**：每月测试烟雾和一氧化碳报警器；伊利诺伊州氡气偏高，建议做一次检测。

**首页**加入：到期保养、本周季节任务、保修 30 天内到期。

## 8. 第三期设计：修还是换、照片与收据

**规则提示**（输出“建议修 / 考虑换 / 建议换”，并列出理由）：

- 使用年限 ÷ 预期寿命：≥ 75% 时关注。
- 是否仍在保修期：在保修期内优先提示走保修。
- 近 12 个月维修次数 ≥ 2：提示考虑更换。
- 经验法则：使用年限 × 本次维修报价 > 更换价格 时倾向更换（HVAC 行业常说的“$5000 法则”的通用形式）。
- 特殊信号：例如老式空调使用 R-22 制冷剂（美国 2020 年起停产），补充制冷剂成本高。
- 页面始终提示：以持证技师的检测和报价为准。

**照片与收据**：使用 Supabase Storage，上传前在浏览器里压缩；文件路径按家庭隔离，并设置存储权限规则。

**报表**：维修费用进入年度 CSV；每台设备的总拥有成本（购买价 + 历次维修）。
