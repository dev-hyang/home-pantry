# 家庭妈妈小助手 🫙

家庭库存与采购清单 + 房屋维护 + 装备清单：记录家里还有多少，按家人的实际消耗速度提醒补货；采购清单家人共享、认领后不会重复买；按库存推荐一日三餐（含孕期、妊娠糖尿病、产后、哺乳追奶模式）；按房型和材料给出维护责任、保养建议，并一次加好常用房屋耗材；床品、电器、自行车、工具等耐用品单独记数量和位置，不参与补货提醒。

架构：**GitHub Pages（纯静态，无构建）+ Supabase 免费层（Postgres + Auth + Realtime）**。前端使用浏览器原生 ES 模块。

## 快速试用

前端使用 ES 模块，浏览器不允许从 `file://` 直接加载，所以本地需要起一个静态服务：

```bash
cd home-pantry
python3 -m http.server 8000
# 打开 http://localhost:8000/ ，自动进入本地演示模式（数据存在浏览器里）
```

部署到 GitHub Pages 后直接访问网址即可，不受这个限制。

GitHub Pages 会把每个文件缓存 10 分钟。页面启动时会比较本次部署时间（`document.lastModified`）和上次记录，发现是新部署就绕过缓存重新拉取全部脚本并自动刷新一次，所以推送后家人不需要手动清缓存；只有部署后 10 分钟内打开的那一次可能仍是旧版本。

## 部署为家庭共享版（约 10 分钟）

1. **创建 Supabase 项目**（免费层即可）。
2. **建表**：Dashboard → SQL Editor。建表脚本（`supabase/` 目录）不随仓库发布，另行提供。
   - **全新部署**：粘贴 `supabase/schema.sql` 全部内容执行。
   - **已有数据、只想升级**：按顺序执行 `supabase/migrations/` 里尚未执行过的文件（第一期 `002_phase1_house.sql`，第二期 `003_phase2_assets.sql`），不会删除数据。
   - 关于 `schema.sql`：脚本会**先删除本应用的旧表和函数（含全部数据），再完整重建**，整个过程在一个事务里，出错会整体回滚。已有数据请先在「设置 → 导出 JSON」备份；登录账号不受影响，但家人需要重新创建 / 加入家庭。
3. **配置登录**：Authentication → URL Configuration
   - Site URL 填 `https://<你的用户名>.github.io/<仓库名>/`
   - Redirect URLs 同样加上这个地址（本地调试可再加 `http://localhost:8000/`）。
   - 默认的邮箱魔法链接即可用；免费层自带邮件发送有频率限制，家庭使用够用，人多时可在 SMTP Settings 接自己的邮箱服务。
4. **填写 `config.js`**：Project Settings → API，复制 Project URL 和 **anon public** key。
   - **手机号登录（可选）**：Authentication → Providers → Phone 打开，并选择一家短信服务商（Twilio、MessageBird、Vonage、Textlocal，各自按条收费，Supabase 免费层不含短信），填入它们的 API 凭据；然后把 `config.js` 里的 `PHONE_LOGIN` 改成 `true`，登录页就会出现“邮箱 / 手机号”切换。手机号登录走短信验证码，家人用手机号和用邮箱登录是两个不同账号，加入家庭时用同一个邀请码即可。中国大陆号码（+86）用 Twilio 等国际短信到达率不稳定，国内家人建议仍用邮箱登录。
5. **发布到 GitHub Pages**：推送到仓库 → Settings → Pages → Deploy from branch（main / root）。
6. 第一位家人登录后“创建家庭”，在设置页复制邀请码发给其他家人，他们登录后“用邀请码加入”。
7. **家主管理**：创建家庭的人自动是家主（`household_members.role = owner`，可以有多位）。家主在设置页可以：重置邀请码；改家人的称呼；把家人设为家主或取消家主；把误加入的人移出家庭。不能移出自己，最后一位家主不能被取消或移出（数据库 RPC 同样校验）。被移出的人下次刷新会回到“加入家庭”页。升级需执行 `migrations/004_owner_management.sql` 和 `005_member_profile.sql`。
8. **邀请码直接进入（推荐给家人）**：Authentication → Sign In / Up → 打开 **Allow anonymous sign-ins**。之后家人在登录页选“邀请码直接进入”，填手机号（只作标识，不发短信）、称呼和邀请码就能进，不用收邮件。原理是匿名账号 + 邀请码加入家庭，RLS 照常生效；邀请码因此成为这个家的钥匙，泄露时创建者在设置页点“重置邀请码”。匿名身份存在该设备浏览器里，换设备需重新用邀请码进入；创建家庭仍需邮箱登录，保证家庭有能找回的主人。不想开放这种方式，把 `config.js` 的 `QUICK_JOIN` 改成 `false`。

本地调试云端版同样用 `python3 -m http.server 8000`，并把 `http://localhost:8000/` 加进 Supabase 的 Redirect URLs。

## 房屋维护（第一期）

- **房屋资料**：地区（北美 / 中国，可随时切换）、房型、地址、建成年份、设施（Furnace、排水泵、地暖、新风等）、外墙 / 屋面 / 地面材料。切换房型会自动预选该房型常见的设施。地址存在房产上，房屋资料和设置页改的是同一个。
- **房屋保险**：资料里填是否有保险、保险公司、保单号、生效 / 到期日、保障范围、年保费，以及理赔代理（姓名、电话、邮箱；概览里可一键拨打 / 发邮件）。只记摘要，不存保单文件。理赔代理字段升级执行 `migrations/009_insurance_agent.sql`。概览状态栏显示一行「🛡️ 房屋保险 State Farm 有效（2026/1/1 – 2026/12/31）保单号 …」；到期前 30 天首页出现“快到期”（尽快级、必须），过期后升为“今天”级。账单里的“房屋保险”负责缴费提醒，这里负责续保。升级执行 `migrations/008_house_insurance.sql`。
- **概览里的清单**：进行中交易的清单（按截止日前 8 项）和本月季节任务都显示在房屋概览；勾过的项不隐藏，保留为实心绿圈 ✔ 加“日期 + 谁已完成”，标题显示“已完成 a / b”。季节任务页、交易页同样保留已完成项。
- **谁负责维护**：按房型列出 10 个部位由自己、HOA、物业、房东中的哪一方负责（以章程、合同或租约为准）。
- **材料保养建议**：只显示你家实际用到的材料，例如 Masonry 的勾缝、Vinyl 的清洗、实木地板的湿度和翻新周期。
- **推荐耗材**：按房屋资料生成清单，勾选后一次加入“房屋耗材”。加入后与普通库存一样增删改查、提醒补货，并进入同一张采购清单。
- **首页「今日」**：储藏和房屋两边需要处理的事合在一张列表，标注来源。
- **模块开关**：设置里可关闭房屋维护，导航和首页只保留厨房储藏；数据不会删除。
- **统计**：房屋耗材花费在图表里合并为“房屋维护”一组；明细 CSV 保留具体分类。

完整的三期设计见 `docs/design-house.md`。

## 房屋维护（第二期）：设备档案、保养记录、季节任务

- **设备档案**（房屋 → 设备）：按房屋资料一键生成炉子、空调、热水器、排水泵、屋顶、软水机、割草机等，寿命和保养间隔给常见经验值（屋顶按屋面材料），默认负责方取自责任归属表；再补品牌、型号、序列号、安装日期、保修到期、购买价格。设备和工具两种，工具字段精简。
- **保养记录**：在设备页下方记检查、保养、维修、更换。检查、保养、更换会按间隔重算下次保养日期，维修不会。填了花费会同时记入花费统计的“房屋维护”组，删除记录时一起删。
- **提醒**：下次保养 30 天内或已逾期、整机或人工保修 30 天内到期，会出现在首页「今日」、房屋概览和设备页顶部。
- **季节任务**（房屋 → 季节任务）：按地区（芝加哥 / 中国模板）、房型和设施生成每个月的检修清单，例如秋季关闭室外水龙头、春季测试排水泵、夏季换滤网。连续月份算同一个窗口，窗口里勾一次即可；每月任务按月勾。勾选后家人都能看到谁做的。首页只列本月没做的。
- **数据**：新增 `assets`、`maintenance_logs`、`seasonal_tasks` 三张表，升级执行 `migrations/003_phase2_assets.sql`；本地演示模式同样可用。
- **记录时间**：物品卡片、设备卡片显示“月/日 更新”（云端版带上是谁），悬停看完整时间；物品和设备编辑页底部显示“添加于 / 更新于”；保养记录显示记录日期；采购清单显示加入日期。

### 第二期验收清单

1. 房屋 → 设备：没有设备时提示“生成设备清单”；生成页按房型、设施列出设备，工具类默认不勾；已有的显示“已有”。
2. 生成后设备卡片显示寿命进度、保养状态、保修状态；点“记保养”跳到设备页并定位到保养记录表单。
3. 在一台设备记一次“保养”并填花费：设备页出现记录，下次保养日期按间隔推算；统计页“房屋维护”金额增加；删除该记录后金额回退。
4. 把某台设备的安装日期改成 2 年前、间隔 12 个月且无记录：首页「今日」出现“保养逾期”。
5. 把保修到期日改成 10 天后：首页和设备页出现“保修快到期”。
6. 房屋 → 季节任务：月份切换；本月任务勾选后变成绿圈 ✔ +“已完成 + 谁 + 日期”，留在列表里不隐藏，刷新后仍在；取消勾选恢复。房屋概览的“本月季节任务”同样显示全部并计数“已完成 a / b”。
6b. 房屋 → 房屋资料：填地址和保险（到期日设 20 天后）→ 概览状态栏出现“🛡️ 房屋保险 … 快到期 · 20 天 … 保单号 …”，首页「今日」出现“房屋保险 快到期”；到期日改成昨天 → 变“已过期”并升到“今天”级。
7. 首页「今日」列出本月没做的季节任务，直接勾选即可完成。
8. 云端版：家人 A 勾的任务、记的保养，家人 B 刷新后可见。

## 首页「今日」与提醒总线

- `js/core/alerts.js` 是提醒总线：储藏补货、房屋耗材、设备保养、季节任务、账单、房产交易各自把提醒翻译成统一形状（来源、严重度、是否必须、到期、房产、动作）并注册；首页、网页标题计数、浏览器通知都从总线取同一份数据，以后的邮件摘要也走这里。新增一种提醒只需写一个适配函数并在 `main.js` 注册，不用改首页。
- 严重度四档：紧急（逾期的账单、必须的交易任务）、今天（今天到期、设备保养逾期）、尽快（一周内到期、待核对的自动扣款、缺货）、留意（少货、临期、本月季节任务）。标题计数只算前三档。
- 首页可切换“按轻重排 / 按房产分”、“只看要紧的”（折叠留意级）、“只看我负责的”（云端且有指定负责人时出现）；偏好存在本机。
- 房产归属：多于一套活跃房产时，提醒、账单清单、账单详情、toast 和通知统一带「🏠 房产名」芯片；单套房产不显示。设备和季节任务改为按家庭全量读取，页面按当前房产过滤，所以切到 A 房产时 B 房产的逾期仍会出现在首页。

## 账单与缴费（B1）

- **账单清单**（账单 → 清单）：水电气、网络手机、HOA / 物业费、房产税、房贷房租、保险、车贷、信用卡、订阅会员、学费托儿、停车。北美（芝加哥 / Cook County）和中国两套常用账单模板，一次建好后再补金额和到期日。每条账单记付款方、账号尾号、登录提示、缴费链接、缴费方式、账单渠道，**不存账号密码或完整卡号**。
- **到期与提醒**：频率（每周到每年、每 N 个月、一次性）+ 每月几号或固定日期（如房产税 03-01 / 08-01），自动算下次到期日。提前提醒天数可多档（默认 7 和 1 天）。手动账单提示“去缴费”，自动扣款账单到期前后提示“核对”；首页「今日」有账单段。自动扣款的卡有效期前 45 天提醒换卡。
- **缴费记录**：在账单页“记一笔”（已缴费 / 已核对 / 跳过），或在概览点“已核对”一键记录；记录后下次到期日推到下一期。有金额的记录同时写入花费统计的“账单”组，年度 CSV 自然包含。金额比最近均值高 15% 标“涨价了”。记录页有今年合计、滞纳金合计、单账单金额趋势和 CSV 导出。
- **概览**：未来 30 天要交多少、每月固定支出（按频率折算，必要 / 非必要分开）、自动扣款占比、要处理的账单、未来 30 天日程。
- **日历导出**：概览“导出到日历”生成 .ics（每条账单未来一年的到期日，带提前提醒），加到手机日历后由系统响铃，不依赖网页是否打开。账单变动后重新导出一次。
- **多房产**：设置页可添加多套房产（自住 / 出租 / 租住），房屋资料、设备、季节任务按当前房产切换，账单可挂到任一房产或与房产无关；账单页可按房产筛选。创建家庭自动带一条默认房产；老数据升级后全部归到默认房产。
- **数据**：新增 `properties`、`bills`、`bill_payments`；`house_profiles`、`assets`、`seasonal_tasks` 挂 `property_id`。升级执行 `migrations/006_properties_bills.sql`。设置里可关闭账单模块。

## 房产生命周期：买入 / 卖出 / 退租（P1 + P2）

- **状态**：看房 → 交易中买入 → 持有（或租住）→ 交易中卖出 → 已卖出（或已退租）；归档后只读；彻底删除只对已归档的开放。看房、签约阶段就可以建房产。
- **交易页**（房屋 → 交易）：开始买入 / 卖出 / 退租流程，填合同日、交割日、价格、律师 / 贷款行 / 经纪人 / 产权公司 / 验房师（只存姓名电话文本）。按伊利诺伊州（芝加哥）流程生成清单，截止日按合同日或交割日推算，分“必须 / 建议 / 可选”，必须项逾期在首页置顶。模板在 `data/deals.js`，可增删或改成其他州。
- **停服务提醒**：卖出和退租清单里，按这套房产挂着的账单自动生成“必须”任务：水费结清证明（Chicago，交割前 21 天）、HOA 通知与付清证明（−14）、还款函（−10）、网络停机（−7）、电 ComEd 与燃气 Nicor / Peoples Gas 最终抄表（−5，冬季不要提前停气）、水 / 垃圾销户（−5）、房屋保险交割日生效取消（−3）、交割后逐条取消自动扣款（+1）、结清最后一期账单（+30）。
- **退出向导**：卖出 / 退租交割后，给该房产每条账单写结束日期（水电气网默认多留 2–6 周等最后一期，其余到交割日），房产状态改为已卖出并归档，交易关闭。不删任何数据；结束日期之后账单不再提醒，清单里显示“已结束”。
- **彻底删除**：设置页对已归档房产点“彻底删除”，输入房产名确认。级联删除账单与缴费记录、设备与保养记录、季节任务、房屋资料、交易；花费统计里的记录保留（报税需要）。
- **数据**：`properties` 加 status / acquired_on / purchase_price / sold_on / sale_price；`bills.ends_on`；新增 `property_deals`、`deal_task_done`。升级执行 `migrations/007_property_lifecycle.sql`。

### B1 验收清单

1. 账单 → 概览点“按模板建账单”，勾选后一次建出 10 条左右；清单按分类分组，到期日已按规则算好（月付的在本月或下月几号，房产税在下一个 3/1 或 8/1）。
2. 把一条账单的下次到期日改成昨天 → 首页「今日」和账单概览出现“逾期”；把一条自动扣款账单改成 2 天后 → 出现“待核对”。
3. 在账单页记一笔有金额的缴费 → 记录出现，下次到期日推一期；统计页“最近的记录”出现该账单，分组为“账单”。
4. 概览点“已核对” → 自动扣款账单一键记录并推期。
5. 清单里切自动扣款开关 → 提示文字变化，刷新后保持。
6. 导出到日历 → .ics 在手机日历能看到到期提醒。
7. 设置里添加第二套房产 → 房屋和账单页出现房产切换条；切到新房产，房屋资料为空、设备为空；账单可挂到它并按它筛选。
8. 云端版：执行 006 后，老家庭的房屋资料、设备、季节任务仍在（归到默认房产）；家人 A 记的缴费，家人 B 刷新后可见。

## 装备（耐用品，只记数量和位置）

物品分三个空间：**储藏**（厨房耗材）、**房屋耗材**（滤网、电池、融雪盐、汽车油液等）、**装备**。前两者按消耗速度提醒补货；装备是不会“用完”的东西，只记有几件、放在哪。

- 装备分类：家居用品（床品、毛巾、季节电器）、出行户外（旅行婴儿用品、推车、自行车、露营、箱包）、汽车装备（千斤顶、搭电线、备胎、车载电器）、工具、园艺工具。
- 装备没有少货线、提醒天数、日均用量和保质期；编辑页选到装备分类时这些字段自动隐藏，保存时清空。首页「今日」、补货提醒、浏览器通知都不会出现装备。
- 装备卡片没有 −/+，数量在编辑页改；因此不会产生消耗记录，也不会污染“各分类使用频率”图。
- 买新装备仍可走采购清单，花费在统计里合并为“装备”一组；年度 CSV 明细保留具体分类。
- 真正会用完的东西放房屋耗材：机油、玻璃水、雨刮片在「汽车养护」分类（房屋资料勾选“有汽车”后推荐清单会带上）；链条油、补胎片放「维修耗材」；草籽、肥料放「季节与庭院」。
- 设置里可关闭装备模块，和房屋维护一样只影响导航，不删数据。
- 数据库不用改：空间由分类 id 推出，`items.category` 仍是字符串。
- 需要记品牌、保修、保养周期的设备（割草机、电动工具、自行车）将来迁入第二期的设备档案，装备空间作为过渡。

## 第一期验收清单

1. 打开首页，看到「今日」：日期、待办数量、补货列表（带“储藏 / 房屋”标签）、采购进度、填写房屋资料的提示。
2. 房屋 → 填写房屋资料：切换“北美 / 中国”，房型卡片和材料选项随之变化；切换房型，设施自动预选。
3. 保存后进入“推荐的房屋耗材”：勾选后添加，跳到房屋耗材列表。
4. 房屋 → 概览：房屋卡片、耗材提醒、责任归属表、所选材料的保养建议。
5. 给一件房屋耗材点几次 −，使其少货，回到首页能看到它；加入采购、填花费和商店后点“已买到”，统计页出现“房屋维护”和该商店。
6. 打开物品编辑页后用手机返回手势或浏览器后退，回到原列表和原滚动位置。
7. 我的 → 设置 → 关闭房屋维护：底部导航不再显示“房屋”，首页只显示储藏的待办；重新打开后一切恢复。
8. 原有功能不受影响：单位换算、采购认领、菜单推荐、统计图表、年度 CSV 导出。
9. 云端版：执行迁移脚本后，家人 A 填写的房屋资料，家人 B 刷新后可见。

## 提醒是怎么算的

| 提醒 | 触发条件 | 说明 |
|---|---|---|
| 缺货 | 数量 ≤ 0 | 最高优先级 |
| 少货 | 数量 ≤ 少货线 | 少货线在物品里设置 |
| 即将告罄 | 预计剩余天数 ≤ 提前提醒天数（默认 3） | 剩余天数 = 数量 ÷ 日均用量 |
| 临期 / 已过期 | 保质期在 3 天内 / 已过 | 菜单推荐会优先用这些食材 |

日均用量优先使用物品里手动填的值；没填则取最近 60 天所有家人点“−”记录的总消耗，除以“首次记录至今的天数”（至少按 7 天算，防止刚开始用时高估）。建议补货量 = 补到够用 14 天或少货线的两倍，取较大者。

“−/+” 的步长按单位：kg、L 为 0.5，g 为 100，其余为 1；精确数量可点物品名编辑。

## 多语言（简体 / 繁體 / English）

- 默认按浏览器语言判断：zh-TW、zh-HK → 繁體，其余中文 → 简体，其它 → English。设置页可手动改，登录页右上角也能切。
- 源码里的简体文案就是翻译键：界面用 `t("添加物品")`，数据名称用 `t(c.name)`。`js/i18n/en.js` 是简体 → 英文字典，缺的键在 English 下回落为简体，不会报错。
- 繁體不维护字典，运行时用 OpenCC（`opencc-js`，简体 → 台灣正體含用词）转换，选繁體时才从 CDN 加载；加载失败就显示简体。
- 自己填写的内容（物品名、设备名、备注、商店）不翻译。演示数据和模板生成的物品名按生成时的语言写入。
- 菜谱按库存匹配食材时，关键词中英文都有（`data.js` 的 `ings`），英文不区分大小写。
- 校验字典是否漏键：把仓库外的 `i18n-keys.js` 那类脚本对 `js/` 和 `data/` 扫一遍即可；新增文案记得同时加进 `en.js`。

## 地区与单位

- 打开网页时按**设备时区**自动判断地区（例如 `America/Chicago` → 美国，`America/Toronto` → 加拿大，`Asia/Shanghai` → 中国）；时区无法判断时退回浏览器语言。设置页可以手动改。注意时区取的是手机系统设置，不是 GPS 定位。
- 北美：美制单位 lb、oz、fl oz、qt、gal，货币 USD / CAD；中国：公制 kg、g、斤、L、mL，货币 CNY。
- 物品按**录入时的单位**保存，界面按当前地区换算显示（kg↔lb、g↔oz、L/mL↔fl oz，斤→lb）。这样国内外的家人共享同一份清单时各看各的单位，消耗日志也始终和存储单位一致。
- 编辑表单里显示换算后的数值；没动过的数字保存时保留原值，避免 kg→lb→kg 来回换算产生误差。
- 采购清单里填的单位与库存单位不同（例如库存按 kg、买的时候写 lb），“已买到”入库时自动换算；无法换算（例如“袋”与“kg”）时会提示手动更新。
- “个、盒、袋”等计数单位不换算。家庭库存用不到长度单位（cm / inch），所以没有加入。

## 统计页

- **采购花费**：本月 / 上月 / 月均；按分类堆叠的月度花费柱状图（近 6 或 12 个月）；任选月份的分类占比环形图；任选分类的月度趋势折线图。只统计当前地区货币的记录。
- **消耗趋势**：单品每周用量（柱）与周末库存水位（线），以及各分类每周使用记录次数。不同物品单位不同，所以分类层面统计的是“次数”而不是数量。
- 花费来源：采购清单点“已买到”时填写的实际花费，或在统计页“补记一笔”。清空“已买到”列表不会删除花费记录。
- **按商店统计**：买到时可填“在哪买”（自动记住上次的商店，并提示用过的商店名）。统计页显示各商店的花费占比、次数、平均每次金额和每月趋势；商店名不区分大小写和多余空格，前 6 家单独显示，其余合并为“其他商店”。
- **年度报表 CSV**：选年份后导出两种文件。“汇总”是 12 个月 × 分类的金额表，加全年合计、分类占比和商店排行；“明细”是每一笔记录（日期、物品、分类、商店、数量、单位、金额、货币）。文件带 UTF-8 BOM，Excel 直接打开中文不乱码；以 `= + - @` 开头的文本会加 `'` 前缀，防止表格公式注入。汇总只计当前地区货币，其他币种在文末注明。
- 图表用固定 viewBox 的 SVG，宽屏和手机各一套画布、由 CSS 媒体查询切换，不依赖 JS 读取窗口尺寸；每个图都可展开数据表。
- 在物品表单里直接修改数量也会记一条“调整”日志，库存水位曲线因此更准确。

## 协同与防重复购买

- 所有数据挂在“家庭”下，**RLS** 保证只有家庭成员能读写；建家、加入家庭走 `security definer` 的 RPC。
- 库存增减走 `adjust_stock()`：行锁 + 写消耗日志，两个人同时点 −1 不会互相覆盖。
- 采购清单对同一库存物品有**唯一索引**（未买到状态下只能有一条）；“我来买”认领后其他家人能看到谁在买；“已买到”会自动把数量加回库存。
- Realtime 订阅 `items`、`shopping_list`，家人改动几乎实时出现；切回页面时也会自动刷新。

## 安全提示

- `config.js` 里的 anon key 本来就是公开的，数据安全完全依赖 RLS——**不要关闭 RLS，也绝不要把 service_role key 放进前端**。
- 所有用户输入在渲染前都做了 HTML 转义，防止 XSS。
- 邀请码泄露时，创建者可调用 `rotate_invite_code(household_id)` 重置（可在 SQL Editor 执行，后续可做成设置页按钮）。
- 免费层项目 7 天无访问会被暂停，日常使用一般不会触发；设置页可导出 JSON 备份。

## 菜单推荐模块（可选功能的现状与路线）

**已实现（v1，零成本、无后端）**
- 内置约 25 道家常菜，标注适用的饮食模式；按库存匹配食材，显示“有/缺”，缺的可一键加入采购清单。
- 五种模式：普通家庭、孕期、妊娠糖尿病、产后恢复、哺乳追奶，各附膳食要点和免责声明。
- 每道菜可跳转“下厨房”搜索做法（只是外链搜索，不抓取对方内容）。

**为什么没有直接“连接”菜谱网站 / App**：国内主流菜谱平台（下厨房、美食天下等）没有开放的公共 API，网页抓取既受浏览器跨域限制，也涉及对方服务条款和版权，不适合放在纯前端里做。

**建议的 v2 方案**
1. 新建 Supabase Edge Function `meal-plan`：读取家庭库存 + 饮食模式 + 过敏/忌口，调用大模型生成一日或一周菜单（JSON 结构：餐次、菜名、食材、份量、营养说明）。
   费用：Supabase 免费层每月含 50 万次 Edge Function 调用，家庭使用远用不完；真正的成本是大模型 API 按用量计费，需要在函数里做频率限制。
2. 模型 API Key 放在 Edge Function 的 Secrets 里，前端只调用 `supabase.functions.invoke("meal-plan")`，不暴露密钥；并在函数里校验调用者是家庭成员、做频率限制控制费用。
3. 加一张 `diet_profiles` 表（孕周、血糖目标、过敏原、是否亲喂等），让推荐个性化。
4. 英文菜谱可接 TheMealDB 等开放 API 作为补充。

**健康内容边界**：妊娠糖尿病、孕期和产后饮食因人而异，页面内容定位为“一般性参考”；涉及血糖控制份量、追奶问题时，界面持续提示以医生、注册营养师或泌乳顾问（IBCLC）的意见为准。
