# 爱家小助手 🫙

家庭库存与采购清单 + 房屋维护 + 装备清单：记录家里还有多少，按家人的实际消耗速度提醒补货；采购清单家人共享、认领后不会重复买；按库存推荐一日三餐（含孕期、妊娠糖尿病、产后、哺乳追奶模式）；按房型和材料给出维护责任、保养建议，并一次加好常用房屋耗材；床品、电器、自行车、工具等耐用品单独记数量和位置，不参与补货提醒。

架构：**GitHub Pages（纯静态，无构建）+ Supabase 免费层（Postgres + Auth + Realtime）**。前端使用浏览器原生 ES 模块。

## 快速试用

前端使用 ES 模块，浏览器不允许从 `file://` 直接加载，所以本地需要起一个静态服务：

```bash
cd home-pantry
python3 -m http.server 8000
# 打开 http://localhost:8000/ ，自动进入本地演示模式（数据存在浏览器里）
```

部署到 GitHub Pages 后直接访问网址即可，不受这个限制。

GitHub Pages 会把每个文件缓存 10 分钟。页面启动时会比较本次部署时间（`document.lastModified`）和上次记录，发现是新部署就绕过缓存重新拉取全部脚本并自动刷新一次，所以推送后家人不需要手动清缓存；只有部署后 10 分钟内打开的那一次可能仍是旧版本。

## 部署为家庭共享版（约 10 分钟）

1. **创建 Supabase 项目**（免费层即可）。
2. **建表**：Dashboard → SQL Editor。建表脚本（`supabase/` 目录）不随仓库发布，另行提供。
   - **全新部署**：粘贴 `supabase/schema.sql` 全部内容执行。
   - **已有数据、只想升级**：按顺序执行 `supabase/migrations/` 里尚未执行过的文件（目前到 `021_item_assets.sql`），不会删除数据。`schema.sql` 当前为 v1.22，已包含全部迁移的结果。
   - 关于 `schema.sql`：脚本会**先删除本应用的旧表和函数（含全部数据），再完整重建**，整个过程在一个事务里，出错会整体回滚。已有数据请先在「设置 → 导出 JSON」备份；登录账号不受影响，但家人需要重新创建 / 加入家庭。
3. **配置登录**：Authentication → URL Configuration
   - Site URL 填 `https://<你的用户名>.github.io/<仓库名>/`
   - Redirect URLs 同样加上这个地址（本地调试可再加 `http://localhost:8000/`）。
   - 默认的邮箱魔法链接即可用；免费层自带邮件发送有频率限制，家庭使用够用，人多时可在 SMTP Settings 接自己的邮箱服务。
4. **填写 `config.js`**：Project Settings → API，复制 Project URL 和 **anon public** key。
   - **手机号登录（可选）**：Authentication → Providers → Phone 打开，并选择一家短信服务商（Twilio、MessageBird、Vonage、Textlocal，各自按条收费，Supabase 免费层不含短信），填入它们的 API 凭据；然后把 `config.js` 里的 `PHONE_LOGIN` 改成 `true`，登录页就会出现“邮箱 / 手机号”切换。手机号登录走短信验证码，家人用手机号和用邮箱登录是两个不同账号，加入家庭时用同一个邀请码即可。中国大陆号码（+86）用 Twilio 等国际短信到达率不稳定，国内家人建议仍用邮箱登录。
5. **发布到 GitHub Pages**：推送到仓库 → Settings → Pages → Deploy from branch（main / root）。
6. 第一位家人登录后“创建家庭”，在设置页复制邀请码发给其他家人，他们登录后“用邀请码加入”。
7. **家主管理**：创建家庭的人自动是家主（`household_members.role = owner`，可以有多位）。家主在设置页可以：重置邀请码；改家人的称呼；把家人设为家主或取消家主；把误加入的人移出家庭。不能移出自己，最后一位家主不能被取消或移出（数据库 RPC 同样校验）。被移出的人下次刷新会回到“加入家庭”页。升级需执行 `migrations/004_owner_management.sql` 和 `005_member_profile.sql`。
8. **邀请码直接进入（推荐给家人）**：Authentication → Sign In / Up → 打开 **Allow anonymous sign-ins**。之后家人在登录页选“邀请码直接进入”，填手机号（只作标识，不发短信）、称呼和邀请码就能进，不用收邮件。原理是匿名账号 + 邀请码加入家庭，RLS 照常生效；邀请码因此成为这个家的钥匙，泄露时创建者在设置页点“重置邀请码”。匿名身份存在该设备浏览器里，换设备需重新用邀请码进入；创建家庭仍需邮箱登录，保证家庭有能找回的主人。不想开放这种方式，把 `config.js` 的 `QUICK_JOIN` 改成 `false`。

本地调试云端版同样用 `python3 -m http.server 8000`，并把 `http://localhost:8000/` 加进 Supabase 的 Redirect URLs。

## 房屋维护（第一期）

- **房屋资料**：地区（北美 / 中国，可随时切换）、房型、地址、建成年份、设施（Furnace、排水泵、地暖、新风等）、外墙 / 屋面 / 地面材料。切换房型会自动预选该房型常见的设施。地址存在房产上，房屋资料和设置页改的是同一个。
- **房屋保险**：资料里填是否有保险、保险公司、保单号、生效 / 到期日、保障范围、年保费，以及理赔代理（姓名、电话、邮箱；概览里可一键拨打 / 发邮件）。只记摘要，不存保单文件。理赔代理字段升级执行 `migrations/009_insurance_agent.sql`。概览状态栏显示一行「🛡️ 房屋保险 State Farm 有效（2026/1/1 – 2026/12/31）保单号 …」；到期前 30 天首页出现“快到期”（尽快级、必须），过期后升为“今天”级。账单里的“房屋保险”负责缴费提醒，这里负责续保。升级执行 `migrations/008_house_insurance.sql`。
- **在房屋页添加房产**：房屋各页顶部的房产切换条带「＋ 添加房产」，概览状态行有「编辑房产」；用的是和设置页同一个表单、同一个保存逻辑（`js/house/property-form.js`），两边始终一致。在房屋页新建后自动切到新房产，接着填资料；归档、设默认、彻底删除仍在设置页。
- **应急信息与关键位置**（资料 → 🚨 应急信息与关键位置）：总水阀、燃气总阀与工具、配电箱位置与回路标签、水表 / 电表 / 气表位置与账户、排水泵位置、路由器 / Mesh 节点与管理地址、安防面板与密码存放处、其他。全是文本，概览里房屋卡下面一张红边可展开卡，爆水管、跳闸时家人一眼找到。存 `house_profiles.emergency jsonb`，升级执行 `migrations/020_house_emergency.sql`。
- **HOA / 物业（Condo 与独栋的差别）**：资料里按房型默认有无 HOA / 物业（Condo、联排、中国电梯公寓默认有，独栋、租住默认无，可改），填名称、管理公司、电话 / 邮箱 / 业主门户、费用与频率、特殊评估（金额、用途、截止日、已缴）、规则与限制（宠物、出租限制、装修审批、停车、安静时段）、备注。概览里有「HOA / 物业」面板（联系方式可拨打 / 发邮件、费用可链到账单）和按房型的须知（Condo：master policy 与 HO-6、22.1 披露、储备金研究；联排：章程里谁修外墙屋顶；中国：维修基金、业委会）。特殊评估未缴在截止前 45 天进首页提醒，逾期置顶。升级执行 `migrations/010_house_hoa.sql`（`house_profiles.hoa jsonb`）。
- **概览里的清单**：进行中交易的清单（按截止日前 8 项）和本月季节任务都显示在房屋概览；勾过的项不隐藏，保留为实心绿圈 ✔ 加“日期 + 谁已完成”，标题显示“已完成 a / b”。季节任务页、交易页同样保留已完成项。
- **谁负责维护**：按房型列出 10 个部位由自己、HOA、物业、房东中的哪一方负责（以章程、合同或租约为准）。
- **材料保养建议**：只显示你家实际用到的材料，例如 Masonry 的勾缝、Vinyl 的清洗、实木地板的湿度和翻新周期。
- **推荐耗材**：按房屋资料生成清单，勾选后一次加入“房屋耗材”。加入后与普通库存一样增删改查、提醒补货，并进入同一张采购清单。
- **首页「今日」**：储藏和房屋两边需要处理的事合在一张列表，标注来源。
- **模块开关**：设置里可关闭房屋维护，导航和首页只保留厨房储藏；数据不会删除。
- **统计**：房屋耗材花费在图表里合并为“房屋维护”一组；明细 CSV 保留具体分类。

完整的三期设计见 `docs/design-house.md`。

## 房屋维护（第二期）：设备档案、保养记录、季节任务

- **设备档案**（房屋 → 设备）：按房屋资料一键生成炉子、空调、热水器、排水泵、屋顶、软水机、割草机等，寿命和保养间隔给常见经验值（屋顶按屋面材料），默认负责方取自责任归属表；再补品牌、型号、序列号、安装日期、保修到期、购买价格。设备和工具两种，工具字段精简。
- **保养记录**：在设备页下方记检查、保养、维修、更换。检查、保养、更换会按间隔重算下次保养日期，维修不会。填了花费会同时记入花费统计的“房屋维护”组，删除记录时一起删。
- **提醒**：下次保养 30 天内或已逾期、整机或人工保修 30 天内到期，会出现在首页「今日」、房屋概览和设备页顶部。
- **季节任务**（房屋 → 季节任务）：按地区（芝加哥 / 中国模板）、房型和设施生成每个月的检修清单，例如秋季关闭室外水龙头、春季测试排水泵、夏季换滤网。连续月份算同一个窗口，窗口里勾一次即可；每月任务按月勾。勾选后家人都能看到谁做的。首页只列本月没做的。
- **数据**：新增 `assets`、`maintenance_logs`、`seasonal_tasks` 三张表，升级执行 `migrations/003_phase2_assets.sql`；本地演示模式同样可用。
- **记录时间**：物品卡片、设备卡片显示“月/日 更新”（云端版带上是谁），悬停看完整时间；物品和设备编辑页底部显示“添加于 / 更新于”；保养记录显示记录日期；采购清单显示加入日期。

### 第二期验收清单

1. 房屋 → 设备：没有设备时提示“生成设备清单”；生成页按房型、设施列出设备，工具类默认不勾；已有的显示“已有”。
2. 生成后设备卡片显示寿命进度、保养状态、保修状态；点“记保养”跳到设备页并定位到保养记录表单。
3. 在一台设备记一次“保养”并填花费：设备页出现记录，下次保养日期按间隔推算；统计页“房屋维护”金额增加；删除该记录后金额回退。
4. 把某台设备的安装日期改成 2 年前、间隔 12 个月且无记录：首页「今日」出现“保养逾期”。
5. 把保修到期日改成 10 天后：首页和设备页出现“保修快到期”。
6. 房屋 → 季节任务：月份切换；本月任务勾选后变成绿圈 ✔ +“已完成 + 谁 + 日期”，留在列表里不隐藏，刷新后仍在；取消勾选恢复。房屋概览的“本月季节任务”同样显示全部并计数“已完成 a / b”。
6b. 房屋 → 房屋资料：填地址和保险（到期日设 20 天后）→ 概览状态栏出现“🛡️ 房屋保险 … 快到期 · 20 天 … 保单号 …”，首页「今日」出现“房屋保险 快到期”；到期日改成昨天 → 变“已过期”并升到“今天”级。
7. 首页「今日」列出本月没做的季节任务，直接勾选即可完成。
8. 云端版：家人 A 勾的任务、记的保养，家人 B 刷新后可见。

## 车辆与检查卡（设计：docs/design-vehicles.md、docs/design-care.md）

- **车辆**（房屋 → 车辆）：车是挂在家庭上的一种设备（不按房产），类型即动力类型（油车 / 混动 / 插混 / 纯电），决定保养模板。记年款、品牌型号、VIN、车牌、里程与年均里程、购车日期、整车与动力总成 / 电池保修、牌照年贴 / 排放检测 / 租赁到期、车险（公司、保单号、起止、保障范围、代理）。
- **保养时间表**：机油、轮胎轮换、滤芯、刹车油、冷却液、12V 电瓶、火花塞、变速箱油、定位、电池健康度、充电设备、召回查询等，按月和按里程取先到的，里程按年均里程推算到日期。保养记录多“保养项目”和“里程”，记了里程会同步更新车辆当前里程；花费记入“车辆”统计组。
- **车辆提醒**：保养项到期 / 逾期；牌照、排放、保险到期前 30 天（必须，过期升“今天”级）；租赁到期前 90 天。
- **检查卡**：设备详情页和季节任务行带「怎么查、什么时候叫人」折叠块：看什么、正常是什么样、自己能做、这些情况约师傅、马上处理、费用、什么时候。已配：沥青 / 混凝土车道、沥青瓦屋顶、暖风炉、热水器、排水泵、中央空调、排水槽清理、壁炉烟囱。
- **检查结论**：保养记录选“检查”时可填结论（正常 / 需保养 / 需维修 / 需更换）。后三者会让设备标“检查：需维修”并进首页提醒（尽快 · 必须），直到记一条保养 / 维修 / 更换。
- **车道**：房屋资料新设施“自家车道”（独栋默认勾选），生成设备时推荐沥青 / 混凝土车道；季节任务加春季查裂缝积水、秋季填缝封层，并带完整判断标准（填缝 / 封层 / 补丁 / 重铺面层 / 整体更换的触发条件与费用）。
- **数据**：`assets.kind` 加 `vehicle`、`property_id` 对车辆为空、`assets.vehicle jsonb`；`maintenance_logs` 加 `result`、`service_item`、`odometer`。升级执行 `migrations/011_vehicles_care.sql`。
- **拥有状态**：车辆档案 → 拥有状态与证照 里选 选购中 / 持有 / 贷款中 / 租赁 / 已卖出 / 已归还（存 `assets.vehicle.status`，另有 `loan_end`、`disposed_on`、`sale_price`）。已卖出 / 已归还的车从车辆列表、首页提醒和设置里的计数退出，收进车辆页底部的「历史车辆」，档案、保养记录、花费都保留，点开还能看、能改。
- **买车 / 卖车 / 租赁归还流程**：复用房产交易的清单引擎（阶段、应完成 / 实际完成日期、✎ 调整、自定义事项、时间线、历史交易），模板在 `data/deals.js` 的 `veh_buy` / `veh_sell` / `veh_return`，阶段为 准备 → 成交 → 提车 / 交车 → 之后；条件支持 `region:na`、`pt:ev` / `pt:ice`、`status:financed` 等。入口：车辆页「开始买车流程」（先建一辆“选购中”的占位车）、车辆枢纽页「买卖 / 归还」；完成是一键确认：买车 → 持有 / 贷款中并写入购车日期与价格，卖车 → 已卖出，归还 → 已归还。页面 `#/house/deal?asset=<id>`。数据：`property_deals.property_id` 可空、新增 `asset_id`、kind 加三种；升级执行 `migrations/018_vehicle_deals.sql`。

## 房屋概览的布局

- 顺序按“最需要知道的在前”：房屋身份卡（地址 / 保险 / HOA 一眼可查，材料与设施折叠）→ 进行中的交易清单 → 本月季节任务（没做的在前，做完的折叠成“已完成 n 项”）→ 设备提醒 → 耗材提醒 → 底部「参考」三块默认折叠（哪些部位归谁维护、HOA / 物业详情、材料保养建议），手机上一屏能看完要做的事。
- 季节任务行（概览与全年任务页同一份）：标题在上、月份 / 备注在下，长标题不再把勾选框挤到单独一行。
- 季节任务页一次只看一个月：顶部「‹ 10 月 ›」换月，手机上左右滑动也能换，不在本月时有“回到本月”。
- **自定义任务**（「＋ 添加任务」）：每年重复（勾月份，连续月份算一个窗口）或一次性（选日期，出现在那个月，逾期升为首页“今天”级提醒）；模板任务旁带“自定义 / 一次性”标签和 ✎ 编辑。数据表 `custom_seasonal_tasks`（按房产；重复任务的完成记录仍走 `seasonal_tasks`，key 为 `c_<id>`），升级执行 `migrations/019_custom_seasonal_tasks.sql`。

## AI 菜单助手

- 储藏 → 菜单 顶部的对话框：输入需求（或点“低糖高蛋白，六人份”“用掉快过期的食材”等芯片）、填人数，模型按当前库存（食材名、数量、单位、临期天数，不含备注）、临期清单和饮食模式生成早 / 午 / 晚菜单，每道菜标出用到的库存和缺的食材，缺的一键进采购清单，可“换一版”。首页「今天吃什么」格子直达。
- 两种模式：**自带 key**（我的 → 设置 → AI 助手：DeepSeek / 通义千问 / Gemini / 豆包 / Kimi / OpenAI / Claude / 自定义兼容接口；key 只存本机浏览器，浏览器直连）；**无 key**（“复制提示词”后粘贴到豆包 / 千问 / ChatGPT 网页）。性价比最高的是 DeepSeek、qwen-turbo、豆包 lite，一次菜单约几分钱；Gemini Flash 有免费额度。
- 固定推荐模块仍按实时库存计算，每餐可单独“换一道”。集成细节见本地的 `docs/ai-integration.md`（不上传）。
- **免费额度内使用**：默认模型改为 Google Gemini（美国可用的免费档），另加 Groq、OpenRouter 免费档。`js/core/ai.js` 的 `FREE_TIER` 记各家免费档的每分钟 / 每天次数（会变，设置里可改），本机 localStorage `hmh-ai-usage` 按服务商计数（Gemini 按太平洋时间 0 点重置）。“只用免费额度”打开时：到上限就不发请求，直接提示“今天的免费额度用完了，预计 {时间} 恢复”，页面上“发送 / 生成”按钮隐藏、只留“复制提示词”；服务商返回 429 时按 Retry-After / retryDelay 记下恢复时间，提到日配额的直接等到下次重置。设置 → AI 助手里能看今天用了多少、剩多少、下次重置，可重置计数。关掉“只用免费额度”就不限制（付费额度）。
- **自定义接口排错**：“自定义”多一项“鉴权头”（Authorization: Bearer 默认 / x-api-key / api-key），key 里多贴的 “Bearer ” 前缀会自动去掉；测试连接把 401 / 403、404、返回网页等情况翻译成能动手查的提示。401 几乎都是 key 和地址不配：地址要填服务商真正的 API 域名（到 /v1 为止），不是官网或模型页；key 要是这个服务发的、没过期。
- **桌面布局**：顶栏、内容、底部页签同一条 920px 的居中列；表单、设置、介绍页不再各自限宽靠左。

## 交易清单：调整日期、自定义事项、时间线视图

- **应完成 vs 实际完成**：交易清单每项右侧的 ✎ 可以改“应完成日期”（州流程推算的日期有出入、晚了或提前时手动调整，保留“推荐日期”并可一键恢复）、填“实际完成日期”（填了即完成，清空即未完成）和备注（延迟原因等）。已完成的事项显示“应完成 · 实际 · 滞后 / 提前 x 天 / 按时完成”；未完成且过期的显示“逾期 x 天”。首页提醒按调整后的日期算。改了合同日 / 交割日，手动调整过的事项不受影响，其余照常重算。
- **自定义事项**：交易页“＋ 添加自定义事项”（或某个阶段页底部），用于模板之外的要求，如 condo / village / HOA 必须申报 intent to sell。可设名称、阶段（默认“补充事项”）、重要程度、应完成 / 实际完成日期、备注，也能删除。
- **时间线视图**：交易页顶部“清单 / 时间线”切换（选择记在本机）。时间线是一条竖线，每项一个圆点（就是勾选框：空心未完成、实心完成、红色逾期），按应完成日期排，标出签约日、交割日和“今天”，没日期的排在最后；内容与清单完全一致。
- **数据**：新增 `deal_task_overrides`（应完成日期调整 + 备注）、`deal_custom_tasks`（自定义事项）；实际完成日期沿用 `deal_task_done.done_on`。升级执行 `migrations/017_deal_task_edits.sql`（没执行前这两项读不到，交易页其余功能照常）。`schema.sql` 升到 v1.18。

## 账单与缴费（B1）

- **账单清单**（账单 → 清单）：水电气、网络手机、HOA / 物业费、房产税、房贷房租、保险、车贷、信用卡、订阅会员、学费托儿、停车。北美（芝加哥 / Cook County）和中国两套常用账单模板，一次建好后再补金额和到期日。每条账单记付款方、账号尾号、登录提示、缴费链接、缴费方式、账单渠道，**不存账号密码或完整卡号**。
- **车辆牌照 / 车贴**：账单分类新增「车辆牌照 / 车贴」，北美模板有「车辆牌照年贴（州）」（伊州约 $151 / 年，纯电 $251，到期月底前在线续）和默认不勾的「Village / City 车贴（sticker）」（很多镇和 Chicago 市另收，$30–$100 / 年）；中国模板有「年检 / 车船税」。几辆车各建一条，到期月份建后补填。
- **订阅与会员**：仍是“订阅”“会员”两个分类（统计颜色不变），但账单多一个“种类”标签（流媒体、云存储、AI 工具、软件 / App、游戏、新闻 / 阅读、健身、会员）和“免费试用到期日”。模板页“订阅与会员”一组约 18 条（Netflix、Spotify、Google One、iCloud+、ChatGPT Plus、Claude Pro、Microsoft 365、Adobe、杀毒 / VPN、App 年费、游戏会员、健身房、Costco、Prime 等；中国另有一组），默认不勾，年付的到期前 30 天提醒。清单里订阅按种类排在一起并带标签；概览多一个“订阅与会员”汇总（每月折算、条数、年付数）。试用到期前 3 天到首页提醒“不续就取消”（必须级）。升级执行 `migrations/012_subscriptions.sql`。
- **到期与提醒**：频率（每周到每年、每 N 个月、一次性）+ 每月几号或固定日期（如房产税 03-01 / 08-01），自动算下次到期日。提前提醒天数可多档（默认 7 和 1 天）。手动账单提示“去缴费”，自动扣款账单到期前后提示“核对”；首页「今日」有账单段。自动扣款的卡有效期前 45 天提醒换卡。
- **缴费记录**：在账单页“记一笔”（已缴费 / 已核对 / 跳过），或在概览点“已核对”一键记录；记录后下次到期日推到下一期。有金额的记录同时写入花费统计的“账单”组，年度 CSV 自然包含。金额比最近均值高 15% 标“涨价了”。记录页有今年合计、滞纳金合计、单账单金额趋势和 CSV 导出。
- **概览**：未来 30 天要交多少、每月固定支出（按频率折算，必要 / 非必要分开）、自动扣款占比、要处理的账单、未来 30 天日程。
- **日历导出**：概览“导出到日历”生成 .ics（每条账单未来一年的到期日，带提前提醒），加到手机日历后由系统响铃，不依赖网页是否打开。账单变动后重新导出一次。
- **多房产**：设置页可添加多套房产（自住 / 出租 / 租住），房屋资料、设备、季节任务按当前房产切换，账单可挂到任一房产或与房产无关；账单页可按房产筛选。创建家庭自动带一条默认房产；老数据升级后全部归到默认房产。
- **数据**：新增 `properties`、`bills`、`bill_payments`；`house_profiles`、`assets`、`seasonal_tasks` 挂 `property_id`。升级执行 `migrations/006_properties_bills.sql`。设置里可关闭账单模块。

## 房产生命周期：买入 / 卖出 / 退租（P1 + P2）

- **状态**：看房 → 交易中买入 → 持有（或租住）→ 交易中卖出 → 已卖出（或已退租）；归档后只读；彻底删除只对已归档的开放。看房、签约阶段就可以建房产。
- **交易页**（房屋 → 交易）：开始买入 / 卖出 / 退租流程，填合同日、交割日、价格、律师 / 贷款行 / 经纪人 / 产权公司 / 验房师（只存姓名电话文本）。按伊利诺伊州（芝加哥）流程生成清单，截止日按合同日或交割日推算，分“必须 / 建议 / 可选”，必须项逾期在首页置顶。模板在 `data/deals.js`，可增删或改成其他州。
- **停服务提醒**：卖出和退租清单里，按这套房产挂着的账单自动生成“必须”任务：水费结清证明（Chicago，交割前 21 天）、HOA 通知与付清证明（−14）、还款函（−10）、网络停机（−7）、电 ComEd 与燃气 Nicor / Peoples Gas 最终抄表（−5，冬季不要提前停气）、水 / 垃圾销户（−5）、房屋保险交割日生效取消（−3）、交割后逐条取消自动扣款（+1）、结清最后一期账单（+30）。
- **退出向导**：卖出 / 退租交割后，给该房产每条账单写结束日期（水电气网默认多留 2–6 周等最后一期，其余到交割日），房产状态改为已卖出并归档，交易关闭。不删任何数据；结束日期之后账单不再提醒，清单里显示“已结束”。
- **彻底删除**：设置页对已归档房产点“彻底删除”，输入房产名确认。级联删除账单与缴费记录、设备与保养记录、季节任务、房屋资料、交易；花费统计里的记录保留（报税需要）。
- **数据**：`properties` 加 status / acquired_on / purchase_price / sold_on / sale_price；`bills.ends_on`；新增 `property_deals`、`deal_task_done`。升级执行 `migrations/007_property_lifecycle.sql`。

## 装备（耐用品，只记数量和位置）

物品分三个空间：**储藏**（厨房耗材）、**房屋耗材**（滤网、电池、融雪盐、汽车油液等）、**装备**。前两者按消耗速度提醒补货；装备是不会“用完”的东西，只记有几件、放在哪。

- 需要记品牌、保修、保养周期的设备（割草机、电动工具、自行车）将来迁入第二期的设备档案，装备空间作为过渡。

## 提醒是怎么算的

| 提醒 | 触发条件 | 说明 |
|---|---|---|
| 缺货 | 数量 ≤ 0 | 最高优先级 |
| 少货 | 数量 ≤ 少货线 | 少货线在物品里设置 |
| 即将告罄 | 预计剩余天数 ≤ 提前提醒天数（默认 3） | 剩余天数 = 数量 ÷ 日均用量 |
| 临期 / 已过期 | 保质期在 3 天内 / 已过 | 菜单推荐会优先用这些食材 |

日均用量优先使用物品里手动填的值；没填则取最近 60 天所有家人点“−”记录的总消耗，除以“首次记录至今的天数”（至少按 7 天算，防止刚开始用时高估）。建议补货量 = 补到够用 14 天或少货线的两倍，取较大者。

“−/+” 的步长按单位：kg、L 为 0.5，g 为 100，其余为 1；精确数量可点物品名编辑。

## 自定义名称的多语言

- 自己起的名字（自定义存放位置、自建 / 改过的分类名、自加的小类）默认按原文显示；繁體由简体自动转换，English 不会自动翻。
- 我的 → 设置 → 语言、地区与单位 → “自定义名称的翻译”：自动列出全家所有自定义名字，每条可填简体 / English / 繁體叫法（繁體留空则自动转换），全家共用。`t()` 先查这张表再查内置字典，所以物品卡片、下拉、筛选、统计里都会跟着变。数据在 `custom_terms` 表（迁移 016）。
- 物品名称不在此列（量太大）；需要的话以后可以加“按物品名翻译”。

## 多语言（简体 / 繁體 / English）

- 默认按浏览器语言判断：zh-TW、zh-HK → 繁體，其余中文 → 简体，其它 → English。设置页可手动改，顶栏右上角有 简体 / 繁體 / EN 快捷切换（登录页也显示）。
- 源码里的简体文案就是翻译键：界面用 `t("添加物品")`，数据名称用 `t(c.name)`。`js/i18n/en.js` 是简体 → 英文字典，缺的键在 English 下回落为简体，不会报错。
- 繁體不维护字典，运行时用 OpenCC（`opencc-js`，简体 → 台灣正體含用词）转换，选繁體时才从 CDN 加载；加载失败就显示简体。
- 自己填写的内容（物品名、设备名、备注、商店）不翻译。演示数据和模板生成的物品名按生成时的语言写入。
- 菜谱按库存匹配食材时，关键词中英文都有（`data.js` 的 `ings`），英文不区分大小写。
- 校验字典是否漏键：把仓库外的 `i18n-keys.js` 那类脚本对 `js/` 和 `data/` 扫一遍即可；新增文案记得同时加进 `en.js`。

## 地区与单位

- 打开网页时按**设备时区**自动判断地区（例如 `America/Chicago` → 美国，`America/Toronto` → 加拿大，`Asia/Shanghai` → 中国）；时区无法判断时退回浏览器语言。设置页可以手动改。注意时区取的是手机系统设置，不是 GPS 定位。
- 北美：美制单位 lb、oz、fl oz、qt、gal，货币 USD / CAD；中国：公制 kg、g、斤、L、mL，货币 CNY。
- 物品按**录入时的单位**保存，界面按当前地区换算显示（kg↔lb、g↔oz、L/mL↔fl oz，斤→lb）。这样国内外的家人共享同一份清单时各看各的单位，消耗日志也始终和存储单位一致。
- 编辑表单里显示换算后的数值；没动过的数字保存时保留原值，避免 kg→lb→kg 来回换算产生误差。
- 采购清单里填的单位与库存单位不同（例如库存按 kg、买的时候写 lb），“已买到”入库时自动换算；无法换算（例如“袋”与“kg”）时会提示手动更新。
- “个、盒、袋”等计数单位不换算。家庭库存用不到长度单位（cm / inch），所以没有加入。

## 统计页

- **采购花费**：本月 / 上月 / 月均；按分类堆叠的月度花费柱状图（近 6 或 12 个月）；任选月份的分类占比环形图；任选分类的月度趋势折线图。只统计当前地区货币的记录。
- **消耗趋势**：单品每周用量（柱）与周末库存水位（线），以及各分类每周使用记录次数。不同物品单位不同，所以分类层面统计的是“次数”而不是数量。
- 花费来源：采购清单点“已买到”时填写的实际花费，或在统计页“补记一笔”。清空“已买到”列表不会删除花费记录。
- **按商店统计**：买到时可填“在哪买”（自动记住上次的商店，并提示用过的商店名）。统计页显示各商店的花费占比、次数、平均每次金额和每月趋势；商店名不区分大小写和多余空格，前 6 家单独显示，其余合并为“其他商店”。
- **年度报表 CSV**：选年份后导出两种文件。“汇总”是 12 个月 × 分类的金额表，加全年合计、分类占比和商店排行；“明细”是每一笔记录（日期、物品、分类、商店、数量、单位、金额、货币）。文件带 UTF-8 BOM，Excel 直接打开中文不乱码；以 `= + - @` 开头的文本会加 `'` 前缀，防止表格公式注入。汇总只计当前地区货币，其他币种在文末注明。
- 图表用固定 viewBox 的 SVG，宽屏和手机各一套画布、由 CSS 媒体查询切换，不依赖 JS 读取窗口尺寸；每个图都可展开数据表。
- 在物品表单里直接修改数量也会记一条“调整”日志，库存水位曲线因此更准确。

## 协同与防重复购买

- 所有数据挂在“家庭”下，**RLS** 保证只有家庭成员能读写；建家、加入家庭走 `security definer` 的 RPC。
- 库存增减走 `adjust_stock()`：行锁 + 写消耗日志，两个人同时点 −1 不会互相覆盖。
- 采购清单对同一库存物品有**唯一索引**（未买到状态下只能有一条）；“我来买”认领后其他家人能看到谁在买；“已买到”会自动把数量加回库存。
- Realtime 订阅 `items`、`shopping_list`，家人改动几乎实时出现；切回页面时也会自动刷新。

## 安全提示

- `config.js` 里的 anon key 本来就是公开的，数据安全完全依赖 RLS——**不要关闭 RLS，也绝不要把 service_role key 放进前端**。
- 所有用户输入在渲染前都做了 HTML 转义，防止 XSS。
- 邀请码泄露时，创建者可调用 `rotate_invite_code(household_id)` 重置（可在 SQL Editor 执行，后续可做成设置页按钮）。
- 免费层项目 7 天无访问会被暂停，日常使用一般不会触发；设置页可导出 JSON 备份。

## 菜单推荐模块（可选功能的现状与路线）

**已实现（v1，零成本、无后端）**
- 内置约 25 道家常菜，标注适用的饮食模式；按库存匹配食材，显示“有/缺”，缺的可一键加入采购清单。
- 五种模式：普通家庭、孕期、妊娠糖尿病、产后恢复、哺乳追奶，各附膳食要点和免责声明。
- 每道菜可跳转“下厨房”搜索做法（只是外链搜索，不抓取对方内容）。

**为什么没有直接“连接”菜谱网站 / App**：国内主流菜谱平台（下厨房、美食天下等）没有开放的公共 API，网页抓取既受浏览器跨域限制，也涉及对方服务条款和版权，不适合放在纯前端里做。

**建议的 v2 方案**
1. 新建 Supabase Edge Function `meal-plan`：读取家庭库存 + 饮食模式 + 过敏/忌口，调用大模型生成一日或一周菜单（JSON 结构：餐次、菜名、食材、份量、营养说明）。
   费用：Supabase 免费层每月含 50 万次 Edge Function 调用，家庭使用远用不完；真正的成本是大模型 API 按用量计费，需要在函数里做频率限制。
2. 模型 API Key 放在 Edge Function 的 Secrets 里，前端只调用 `supabase.functions.invoke("meal-plan")`，不暴露密钥；并在函数里校验调用者是家庭成员、做频率限制控制费用。
3. 加一张 `diet_profiles` 表（孕周、血糖目标、过敏原、是否亲喂等），让推荐个性化。
4. 英文菜谱可接 TheMealDB 等开放 API 作为补充。

**健康内容边界**：妊娠糖尿病、孕期和产后饮食因人而异，页面内容定位为“一般性参考”；涉及血糖控制份量、追奶问题时，界面持续提示以医生、注册营养师或泌乳顾问（IBCLC）的意见为准。

## 预算（账单 → 预算）与花费打印

- **预算**：填收入（按月或按年）和储蓄比例（默认 20%）。预算 = 收入 − 固定账单（取账单项目的每月折算）− 储蓄 = 每月可支配额，再按过去 6 个月的花费比例分给 日常储备 / 房屋维护 / 车辆 / 装备 / 其他（没有历史时用常见比例）；每类可以手动改，留空用建议值。
- **图表**：每月花费构成（账单 vs 其他）；每月实际花费（柱）对预算和收入（线）；本月各类进度条（竖线 = 本月已过去的比例）；年度进度和预计全年花费；应急金建议（必要账单 × 3–6 个月）。
- **超预算提醒**：本月可支配花费超过预算（尽快）或用掉 85%（留意），以及某一类超预算，会出现在首页“注意事项”里。
- **购物清单**：加入时可填“预估金额”，清单上方会给预算提示（够不够、分期、预存）。
- **大额购物规划**：输入价格、算进哪一类、打算什么时候买，给出一次付清 / 3·6·12 期分期 / 每月预存到促销日（总统日、618、Memorial Day、Prime Day、Labor Day、国庆、Prime 秋季大促、双十一、黑五、网络星期一、Boxing Day）的方案，并列出折扣和返利渠道。促销日按规则推算，Prime 类标“约”，以商家公告为准。
- **数据**：收入和预算存在 `household_budgets`（升级执行 `migrations/022_budgets.sql`，schema v1.23；没执行时预算页能打开，但保存会提示先执行迁移）；演示模式存本机。
- **打印**：设置 → 打印新增“花费统计”（近 3 / 6 / 12 个月或今年以来：按月、按分类、明细）和“预算”；花费页的“打印”按当前搜索 / 筛选打印明细。

## 预算联动：库存、账单、设备，以及理财小功能

- **分区预算**：账单（固定）、日常储备（储藏）、房屋维护（房屋耗材 + 维修保养）、**大件家电**、车辆、装备、其他。大件 = 单笔 ≥ 门槛（默认 300，人民币 2000，可改）的购买，账单、车辆和维修保养不算；设了设备“更换估价”和“常见寿命”后，大件预算按设备寿命每月预存（估价 ÷ 寿命），最多占可支配额 35%。
- **联动库存**：补货预估——库存告急的物品和采购清单里没买的，按你以前买它的花费（最近 3 次的中位数，没有就按同分类）估价，对比日常储备本月剩余；采购清单页顶部也显示这一行。
- **联动账单**：本月已缴 / 还要交 / 逾期、涨价账单、每月折算最高的固定账单；订阅与固定账单年成本（订阅可标“考虑取消”）；现金流预测（未来 90 天账单，填发薪日后算最紧的时点）。
- **理财小功能**：储蓄目标（按完成日期算每月该存多少，可把月度结余存进目标）、月度复盘（上月超预算 / 有结余的类别、最大几笔、实际结余）、家庭分摊（按“谁记的账”当付款人，可设占比，算谁补给谁）。
- 这些设置（大件门槛、发薪日、储蓄目标、订阅标记、分摊占比）存在 `household_budgets.cat_budgets` 里以下划线开头的键，不需要新迁移。

## 收入与预算的权限（我的 → 设置 → 收入与预算）

- **每个人的收入是私有的**：存在 `member_incomes`（迁移 023，行级安全：本人只能读写自己的一行，家主能读写全家的）。非家主只看得到、改得了自己的收入。
- **家主**还能看到每个人的收入和全家合计、调整储蓄比例、重新生成预算；预算本身（各类金额）是全家共用的快照，存在 `household_budgets.cat_budgets._plan`，其他家人能看到各类预算和进度，但看不到收入、计划储蓄这类由收入推出的数字。
- 填好收入后家主会**自动生成**第一版预算；之后有人更新了收入，或家主改了比例，会出现“要重新生成预算吗？”的提示（你改过的各类金额保留）。没有预算时，账单 → 预算页会给出“去设置收入”的链接。
- 不定期的一次性收入（例如卖二手）不进预算；兼职 / 副业填一个大概的月均。
- 说明：“只有家主能改比例”是界面层面的限制；收入的可见性由数据库行级安全保证。

- **多份收入**：每个人的收入是一行一张卡片（来源、金额、每月 / 每年、删除），可以添加多份（主业、兼职…）；删除整张卡片点两次确认并立即保存，其余改完点“保存”。存 `member_incomes.lines`（迁移 024，schema v1.25）。

## 房产税 / 保险走 Escrow（含在房贷月供里）

- 账单的缴费方式新增“**Escrow 代缴**”（迁移 025，schema v1.26）。房产税、房屋保险由贷款方从月供里代缴时选它：不提醒到期、不进“未来 30 天要交”和现金流、不重复计入每月预算（金额照填税单 / 保单上的年额，方便看全年成本）。
- **房贷**那条账单填含 Escrow 的总月供；清单里房贷会标“含 Escrow 约 $X/月”，预算页“固定账单”里也会说明这部分已包含在房贷里。
- **Escrow 年度核对提醒**：有房贷、且同一房产上有 Escrow 代缴的账单时，账单概览出现“Escrow 年度核对”卡片：选每年哪个月提醒（默认 1 月）；到那个月起首页“注意事项”出现“核对 Escrow 年度分析，更新房贷月供”（留意级，下个月还没处理升为尽快级），带“改月供”和“已更新”按钮，点“已更新”后今年不再提醒。提醒月份和已更新的年份存在预算设置里（`_escrow`），不需要新迁移。
- **账单模板**新增“房产税（Escrow 代缴）”和“房屋保险（Escrow 代缴）”（默认不勾选）：走 Escrow 的家庭勾它们，不要勾第一期 / 第二期房产税和普通的房屋保险。
- **花费里的“商店 / 收款方”**：账单缴费记的花费按**缴费当时**记下的收款方显示（中途换了收款方，历史不改写；写错了可以在花费记录里点名称改）；账单、订阅、保险等没有商店的花费用账单的**收款方**（Google One、贷款公司、HOA…），收款方没填就用账单名；只有真正没有任何名称的才归到“未填写商店”。以后记缴费时，没填收款方会直接用账单名记。
- **房产筛选**：账单概览和清单里原来占一行的“全部房产 / 房1 / 房2”芯片导航改成一个下拉筛选（默认全部房产；只有一套房产时不显示）：概览放在标题行，清单放在搜索栏里。
- **缴费记录可编辑**：账单 → 清单 → 某条账单 → 缴费记录，以及 账单 → 记录 页里，点记录的日期（链接）就把它带进表单修改日期、金额、状态、方式、确认号、滞纳金、备注；不会动账单的下次到期日，已记过的花费统计跟着改（金额变 0 / 跳过会删掉那笔花费）。
- **房屋子页路径**：房屋 / 房产 / 页面（例如 房屋 / xx房 / 概览），“房屋”这一级不再消失；车辆是 房屋 / 车辆。
- **面包屑带房产**：账单页和设备页的路径统一成“来源 / 房产 / 账单（设备）名 / 当前块”，例如 账单 / xx房 / 电费 / 缴费记录；点房产回到这套房产的账单清单（设备则回到这套房产的设备保养）。车辆是全家的，路径里没有房产。
- **路径层级统一**：账单 / 房产 / 账单名；房屋 / 房产 / 设备保养 / 设备名；房屋 / 车辆 / 车名；储藏 / 库存（房屋耗材）/ 物品；二级页显示完整层级（账单 / 清单 / 常用账单、房屋 / 房产 / 设备保养 / 生成设备、储藏 / 库存 · 房屋耗材 / 推荐耗材）。第一级不再随“从哪个页面进来”变化。路径里上级是主色链接，悬停 / 点击时才出现下划线。
- **账单清单的缴费方式筛选**：搜索栏里新增“缴费方式”下拉，列出全部方式（网上缴费、自动扣款、邮寄支票、电话缴费、现场缴费、Escrow 代缴），代替原来的 全部 / 自动扣款 / 手动缴费 芯片。

- **花费记录可编辑**：账单 → 花费 → 花费记录里点名称，就地改名称、分类、金额、商店、日期（数量和单位不动）；账单缴费记的花费，点名称跳到那条缴费记录的编辑页，改那里会同步花费。
- **录入购物的购买日期**：日期的优先级是 你在录入页填的“购买日期” > 小票照片 / 粘贴文字里读到的（也认“上周六”“10/18”这类说法，不接受未来日期）> 今天。录入页和确认页都能改日期，确认页会注明日期的来源；没读到日期时会提醒先用的是今天。所以拍照时把日期拍进去最好；补记以前的购物，在录入页选那天（或确认页改）就行，花费统计按那天记。
- **补记默认只记花费**：录入购物时购买日期是过去的日子（补记），每一行默认“只记花费，不入库”（东西多半已经用掉），确认页有提示；要加库存的行再改“放进库存”。改日期时，没手动选过的行会跟着切换默认；日期是今天则照常（匹配已有物品或新建）。
- **缴费记录可改收款方**：新记 / 编辑缴费记录的表单里有“收款方”，写到那笔花费上（只改这一条，账单本身的收款方不变，旧记录保留当时的名字）。
- **账单概览的“本月账单”**：本月到期或已缴过的账单一张列表——已缴的标“✓ 已缴”（缴费日和金额），没缴的标待缴 / 今天到期 / 逾期，标题写“已缴 N / 共 M 笔，还要交 $X”；记完缴费，状态马上变成已缴。
- **新记缴费的收款方默认带入**账单的收款方，账单没填收款方就用账单名，不留空。
- **物品可以“不再提醒”**：试过不好吃、或暂时用完不想补货的物品，在注意事项里点“不再提醒”（或在物品编辑页的“补货提醒”里选暂停 30 / 90 天、一直不提醒），它就不再出现在注意事项、提醒数和“一键加入采购”里；物品列表里留一个“🔕 不提醒”标记。下次给它补货入库会自动恢复提醒，也可以随时在编辑页改回“正常提醒”。只影响缺货 / 少货 / 即将告罄，临期提醒照常。存 `items.alert_mute_until`（迁移 030，schema v1.31；没执行迁移时点“不再提醒”会提示先执行，其余功能照常）。
